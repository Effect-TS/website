Part 1 builds the core of reflex in a single file that runs in your browser,
one Effect idea per lesson, starting here.

Reflex raises alerts. The first version of an alert is one log line,
`expense 1200 over 500`. The editor already holds a file that prints it, and
by the end of this lesson you will have printed it twice from one value.

In this lesson you will:

- read a file that creates an Effect and runs it
- learn that an Effect describes work, and that running it is a separate step
- read the success type of an Effect in the editor
- combine two Effects into one with `Effect.andThen`

## 1. Read the file

Look at `program` in the editor:

<LessonCode

  declaration="program"
/>

Run the file. The terminal prints one log line with the message
`expense 1200 over 500`.

`Effect.log(...)` does not log anything when it is called. It returns a value
that describes logging. That value is an **Effect**. `program` holds it, and
nothing happens until something runs it.

## 2. Find the run line

Look at the last line of the file, `NodeRuntime.runMain(program)`. This is
what runs the Effect. `runMain` takes a description and performs the work it
describes.

Every Part 1 lesson ends with this line. Leave it as it is. You write it
yourself in
[Using FileSystem and NodeRuntime.runMain](/learn/part-2/11-your-program-your-entrypoint).

## 3. Read the type

Hover `program`. The type is `Effect<void, never, never>`.

An Effect type has three type parameters: `Effect<Success, Error, Requirements>`.

- The **success type** is what you get back when the Effect runs. Logging
  gives back nothing, so it is `void`.
- The **error type** says how the Effect can fail. `never` means it cannot.
- The **requirements type** says what the Effect needs before it can run.
  `never` means nothing.

Only the success type matters in this lesson. The error type is the subject of
[Defining errors with Schema.TaggedError](/learn/part-1/04-failure-you-can-see),
and the requirements type is the subject of
[Defining a service with Context.Service](/learn/part-1/08-a-place-for-rules).

## Try it

Run the same description twice.

1. Rename the logging Effect to `alert`, so you have a value to reuse.
2. Replace `program` with `Effect.andThen(alert, alert)`.
   `Effect.andThen(first, second)` describes running `first`, then `second`.
3. Run the file. The terminal prints the message twice. You built one
   description and ran it once, and it logged two lines.
4. Hover `program`. The type is still `Effect<void, never, never>`, because
   the second log gives back nothing, like the first.

## What you learned

- `Effect.log(message)` returns an Effect, a value that describes logging.
  Nothing is logged until the Effect runs.
- `NodeRuntime.runMain(program)` runs an Effect.
- An Effect type reads `Effect<Success, Error, Requirements>`. The success
  type is what the Effect gives back when it runs.
- Effects are values, so you can combine them. `Effect.andThen(a, b)` is one
  Effect that runs `a`, then `b`.
- A description that nothing runs does nothing, and TypeScript does not warn
  you. The next lesson,
  [Using Effect.gen to write programs](/learn/part-1/03-steps-in-order), shows
  what that looks like.
