The service declaration let you write evaluation code without choosing
where to store the rules. That choice is still missing, which is why
`NodeRuntime.runMain(program)` has a type error. To run the program, you
need to construct a `RuleStore` and provide it to the Effect that uses it.

Start with an in-memory store. Once it works, replace it with a second
store containing different rules, without changing the evaluation code.

## Building the store with a layer

A **layer** describes how to build a service. With
`Layer.effect(RuleStore, effect)`, the supplied Effect constructs the
implementation to use for `RuleStore`.

Add `Layer` to the `effect` import. Put the `largeExpense` and `malformed`
constants back, above the class. Then add the layer to the class as a static
member, so `RuleStore.layer` sits next to the declaration:

```ts
static readonly layer = Layer.effect(
  RuleStore,
  Effect.sync(() => {
    const rules = new Map([["large expense", largeExpense], ["malformed", malformed]])
    return RuleStore.of({ list: Effect.sync(() => Array.from(rules.values())) })
  })
)
```

`Effect.sync` delays the synchronous code in its callback until the
Effect runs. Here, the `Map` is created when the layer is built, rather
than when the file loads. `RuleStore.of({ list: ... })` lets TypeScript
check that the object implements the service's interface. Its `list`
Effect reads the map's values into an array when it runs.

## Providing the store to program

Attach `Effect.provide(RuleStore.layer)` to `program` with `.pipe`.

Hover `program`. The type is `Effect<void, SchemaError, never>`. The
requirements type is back to `never`: the layer supplies the `RuleStore`
that `evaluateAll` needs. There are no remaining service requirements, so
the run line no longer has a type error.

Run the file. The laptop gets its alert from the large expense rule, then the
malformed rule stops the run with its `SchemaError`, as it did two lessons
ago.

1. Add a second static member, `layerFixtures`, built the same way as
   `layer`, holding `largeExpense`, `withinBudget` and `veryLarge`.
2. Change one line, the `Effect.provide` on `program`, to provide
   `RuleStore.layerFixtures`.
3. Run the file. Three alert lines print for the laptop:
   `expense 1200 over 500`, `expense 1200 under 5000` and
   `expense 1200 over 1000`. Then three `skip: missing field amount` lines
   print for the taxi, and the program finishes normally.

`evaluateAll`, `evaluate` and the rest of `program` did not change. They
use the service's interface; only the layer chooses the implementation.
You will use this separation again in
[Writing tests with @effect/vitest](/learn/part-2/13-first-tests) to supply
a test store, and in
[Storing data in SQLite with SqlClient](/learn/part-3/17-survive-a-restart)
to replace the in-memory store with SQLite.

This separation does mean you need to check the provided layer when
following the code. `yield* RuleStore` identifies the service being used,
but the layer passed to `Effect.provide` determines which implementation
runs.
