## Locating the failed call

Under the `SchemaError`, look for a line beginning `at evaluate (`. That is
the name we supplied, and the next line, `at evaluate (definition)`, points
to the function's declaration. The error now connects the bad field to a
particular call in our program.

Each call to a function made with `Effect.fn` runs inside a **span** with
that name. A span records an operation's name, start time, duration and
outcome, and `runMain` includes the span's name when it prints a failure.

For now the name only appears in a text report. Later we'll connect a
[trace viewer](/learn/part-2/16-the-picture-you-already-know) and see the
same spans on a timeline, where these names identify each operation.

## Try it

`evaluate` does two things, decoding the rule and checking the expense, and
this failure happened during decoding. We can say so by giving the decode
step its own name:

1. Turn `decodeRule` into a function made with `Effect.fn("decodeRule")`
   that takes the JSON string and decodes it.
2. Run the file and read the failure. It names both steps: `at decodeRule`
   first, then `at evaluate` under it. The decode failed, and it was running
   inside `evaluate`.

Two names now tell us where the failure happened and what called that
operation. Name the steps where that information helps, and leave small
helpers like `matches` as plain TypeScript. Each span costs a little at
runtime, and exporting spans later adds network traffic.

Next we'll stop passing each rule to `evaluate` by hand. Reflex needs a way
to find all of its rules, whether they live in memory for now or in a
database later.
