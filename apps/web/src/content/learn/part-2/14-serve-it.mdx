`main.ts` builds an Engine, runs it once and exits, and the memory stores go
with it. Reflex should hold its rules and accept events whenever they
happen, from a script, a cron job or a phone. In this lesson the engine
becomes a server: one process holding one Engine and its stores, answering
HTTP on port 3000.

In this lesson you will:

- describe an HTTP API as a value with `HttpApi`
- implement that API with handlers
- run a server until it is stopped, with `Layer.launch`
- send a typed error over HTTP as a status code

## 1. Define the API

Create `src/api/Api.ts`. `HttpApi` describes the server before any of it
runs. An **endpoint** is a method, a path, and the schemas for what goes in
and comes out. For example,
`HttpApiEndpoint.post("create", "/", { payload: Rule, success: StoredRule })`
creates a rule.

Endpoints are grouped, and the groups make up the API:

- `rules`: create, list, get, remove, and `POST /rules/:id/run` to run one
  rule against an event
- `events`: `POST /events` submits an event to every matching rule
- `runs`: `GET /runs?ruleId=&limit=` lists the run history

<LessonCode file="checkpoints/14/src/api/Api.ts" />

Every schema here already exists in the domain. The API adds no types of its
own. `get`, `remove` and `run` declare `RuleNotFound` as their error, with
`HttpApiSchema.status(404)`.

## 2. Write the handlers

Create `src/server/Api.ts`. `HttpApiBuilder.group(Api, "rules", ...)`
implements one group. Inside an `Effect.fn`, you `yield*` the services you
need. Then `handlers.handleAll({...})` takes one function per endpoint:

<LessonCode file="checkpoints/14/src/server/Api.ts" />

Each handler gets the decoded `params`, `query` and `payload`. The compiler
checks what it returns against the endpoint's success schema, and how it
fails against the endpoint's declared errors. Each handler is a single call
into the services from the last two lessons.

## 3. Launch the server

Create `src/server/main.ts`. The server program is layers all the way down:

- `HttpApiBuilder.layer(Api)` turns the handlers into routes.
- `HttpApiScalar.layer` adds documentation at `/docs`.
- `HttpRouter.serve` serves both.
- `NodeHttpServer.layer` listens on port 3000.

The Engine, the memory stores and `NodeServices.layer` are provided
underneath.

<LessonCode file="checkpoints/14/src/server/main.ts" />

A layer normally builds, hands over its services, and is done. A server has
nothing to hand over. It should keep running. `Layer.launch` builds the layer
and keeps it running until the program is interrupted, which `runMain` does
when you press Ctrl-C.

```sh
pnpm dev:server
```

The server starts and restarts on every file change. Every restart empties
the memory stores. [Storing data in SQLite with SqlClient](/learn/part-3/17-survive-a-restart)
fixes that.

## 4. Call it

In a second terminal, create a rule, submit an event, and read the run:

```sh
curl -X POST localhost:3000/rules -H 'content-type: application/json' -d @fixtures/rules/expense.json
curl -X POST localhost:3000/events -H 'content-type: application/json' -d @fixtures/events/laptop.json
curl localhost:3000/runs
```

The first call answers with the stored rule and its `id`. The second answers
with one `succeeded` outcome. The third lists the run row.

Now ask for a rule that does not exist:

```sh
curl -i localhost:3000/rules/nope
```

It answers `404 Not Found` with the error as the body:

```text
{"_tag":"RuleNotFound","id":"nope"}
```

The handler failed with the same `RuleNotFound` the store fails with. Because
the endpoint declares that error with a 404, the server sends it with that
status. A request that does not match a schema never reaches a handler at
all. A rule without an action, or `limit=abc`, gets a 400 from the decoder.

Open [http://localhost:3000/docs](http://localhost:3000/docs). The API
documentation is generated from the same value.

## Try it

`GET /runs?limit=-1` comes back with every run except the oldest, because
`RunLog.list` hands the number straight to `slice`. `limit=1.5` is accepted
too. The schema lets through numbers that are not a count.

1. In the `runs` query, make `limit` a whole number greater than 0 with
   `Schema.Int.check(Schema.isGreaterThan(0))`.
2. Notice that nothing in the handlers or in `RunLog` has to change.

Check your work with `pnpm dev:server` running:

```sh
curl -i 'localhost:3000/runs?limit=-1'
curl -i 'localhost:3000/runs?limit=1.5'
curl -i 'localhost:3000/runs?limit=2'
```

The first two answer 400 and the last answers 200. The hint and the changed
file are in `exercises/14/`. From the next checkpoint on, the reference
solution includes this change.

## What you learned

- The API is one value. Handlers implement it group by group.
- A typed error declared on an endpoint travels over HTTP with a status
  code.
- Input that does not match a schema is rejected before any handler runs.
- `Layer.launch` runs a server until it is interrupted.
- The cost is a second process to keep running, and a memory store that
  resets with it. [Calling the API with HttpApiClient](/learn/part-2/15-talk-to-it)
  derives a client from the same value.
