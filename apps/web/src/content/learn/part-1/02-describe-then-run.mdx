Reflex checks expenses and raises alerts. For now, an alert is just a log
line: `expense 1200 over 500`. The editor contains a program that prints it.
Throughout Part 1, you will build on this single file in your browser,
adding one Effect concept at a time.

Start by running the program, then change it to print the same alert twice.
That small change introduces a distinction you will use throughout the
course: describing work is separate from running it.

## A value that describes logging

Look at `program` in the editor:

Run the file. The terminal prints one log line with the message
`expense 1200 over 500`.

Calling `Effect.log(...)` creates a value that describes logging. That value
is an **Effect**, and `program` refers to it. The call itself does not print
the message; the logging happens only when the Effect runs.

## Where the work runs

Look at the last line of the file, `NodeRuntime.runMain(program)`. This is
what runs the Effect stored in `program` and produces the log line you saw.

Every Part 1 lesson ends with this line. Leave it as it is. You write it
yourself in
[Using FileSystem and NodeRuntime.runMain](/learn/part-2/11-your-program-your-entrypoint).

## Reading an Effect type

Hover `program`. The type is `Effect<void, never, never>`.

An Effect type has three type parameters: `Effect<Success, Error, Requirements>`.

- The **success type** is the result of a successful run. Logging has no
  useful result, so this type is `void`.
- The **error type** lists the errors an Effect can fail with. Here it is
  `never`, meaning there are no typed failures.
- The **requirements type** lists the services an Effect needs. Here it is
  also `never`, because logging needs no services supplied by your program.

For now, focus on the success type. The error type is the subject of
[Defining errors with Schema.TaggedError](/learn/part-1/04-failure-you-can-see),
and the requirements type is the subject of
[Defining a service with Context.Service](/learn/part-1/08-a-place-for-rules).

## Try it

Because an Effect is a value, you can reuse it when building a larger
program. Combine two uses of the same logging Effect:

1. Rename the existing `program` constant to `alert`.
2. Add a new `program` constant set to `Effect.andThen(alert, alert)`.
   `Effect.andThen(first, second)` describes running `first`, then `second`.
3. Run the file. The terminal prints the message twice. The combined
   `program` runs once and performs the logging Effect twice.
4. Hover `program`. The type is still `Effect<void, never, never>`, because
   the second logging Effect also has a `void` result.

It is also possible to create an Effect and never run it. TypeScript will
not warn you about this. In
[Using Effect.gen to write programs](/learn/part-1/03-steps-in-order), you
will run several Effects in order and see what happens if you accidentally
leave one out.
