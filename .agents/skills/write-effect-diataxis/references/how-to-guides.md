# How-to guides

Write a goal-oriented guide for a competent reader solving a concrete problem
in real work.

## Define the task

- State the concrete result and the conditions in which the guide applies.
- Assume the reader already has the basic Effect competence required by the
  task. Link to a tutorial when they do not.
- Keep the scope narrow enough that success has an observable meaning. Do not
  frame an open-ended subject such as building an entire application as a
  how-to guide.
- Name the page after the result or problem, not after a feature tour.

## Guide action

- Start from the reader's real situation and lead by the safest reliable path
  to the goal.
- Prefer steps, decisions, and complete commands over conceptual exposition.
- Include alternatives only when the reader must choose between them. State
  the condition that selects each path.
- Address realistic constraints, failure modes, and recovery that affect task
  completion.
- Keep examples minimal but usable in the context promised by the page.
- End when the goal is achieved. State how the reader can verify the result.

## Keep teaching out of the path

- Do not manage a learning journey, introduce APIs one at a time for practice,
  or add tutorial checkpoints.
- Explain an Effect API only as much as the current decision requires. Leave
  complete signatures and options to reference material.
- Link to explanation for background, design rationale, and broader tradeoffs.
- Remove digressions that do not change what the reader should do.

## Review the guide

Verify that a competent reader can identify their situation, follow one
coherent path, handle the relevant failure cases, and confirm completion
without reading unrelated theory.
