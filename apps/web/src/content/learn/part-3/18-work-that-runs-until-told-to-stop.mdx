Everything the server does so far is an answer to a request. The next lesson
adds work nobody asks for in the moment: an interval rule polls a URL every
few seconds for as long as the server runs. Before that loop does anything
real, it has to stop cleanly when the server stops, and say so. In this
lesson you build a heartbeat, a loop that only logs, so that stopping is the
only thing to watch.

In this lesson you will:

- repeat an effect on a schedule with `Effect.repeat` and `Schedule.spaced`
- run the loop in the background with `Effect.forkScoped`, tied to a layer's
  scope
- put cleanup in `Effect.onInterrupt` and see it run on Ctrl-C

## 1. Write the heartbeat

Create `src/Heartbeat.ts`. It logs how many rules are stored, once at startup
and then every 30 seconds:

<LessonCode file="checkpoints/18/src/Heartbeat.ts" />

Read it from the inside out:

- The inner `Effect.gen` block is one beat: list the rules, log the count.
- `Effect.repeat(Schedule.spaced("30 seconds"))` runs the beat, then runs it
  again 30 seconds after each run ends, forever. The first run happens at
  once. A `Schedule` is a value that describes when to go again.
- `Effect.onInterrupt` runs its effect when the loop is interrupted, and only
  then. A loop that never ends on its own has exactly one way to stop, so the
  log goes there.
- `Effect.forkScoped` starts the loop on a fiber of its own and ties that
  fiber to the current scope. A fiber is a piece of work that runs alongside
  the rest of the program. Building the layer finishes straight away, and the
  loop carries on in the background.

## 2. Add it to the server

`Layer.effectDiscard` builds a layer from an effect without providing any
service. Like every layer, it has a scope. The scope opens when the layer is
built and closes when the program that built it ends. `forkScoped` puts the
loop in that scope, so when the scope closes, the loop is interrupted,
`onInterrupt` logs, and only then does the layer finish closing.

## 3. Stop it with Ctrl-C

Press Ctrl-C. The last log line before the process exits is:

```text
heartbeat stopped
```

You did not write a signal handler. This is the chain of events:

1. `runMain` turns Ctrl-C into an interruption of the main fiber.
2. `Layer.launch` was holding the server open. Interrupted, it closes the
   layer.
3. Closing the layer closes its scope, which interrupts the heartbeat.
4. The heartbeat's `onInterrupt` logs.

## What you learned

- A loop is an effect with `Effect.repeat` and a `Schedule`.
- `Effect.forkScoped` ties a loop to the scope that started it, so it stops
  when that scope closes.
- `Effect.onInterrupt` is where cleanup goes.
- The cost is a fiber that does nothing most of the time.
- The next lesson,
  [Running rules on a schedule with FiberMap](/learn/part-3/19-rules-on-a-clock),
  replaces the heartbeat with one loop per interval rule. Each of those has to
  stop on its own when its rule is removed, not only when the server stops.
