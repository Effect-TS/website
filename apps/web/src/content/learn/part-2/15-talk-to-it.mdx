curl works, but nobody wants to type
`-H 'content-type: application/json' -d @...` for every rule. Reflex needs a
command line.

The obvious version calls `fetch` with hand-written URLs and bodies. It would
drift. Rename a field or a path on the server, and the CLI still compiles, then
fails when you run it. In this lesson you build a CLI that can't drift, because
its client comes from the same API value the server implements.

You will learn:

- how to derive a typed client from an `HttpApi`;
- how to read configuration from the environment with `Config`;
- how a typed error from the server comes back as the same class;
- how to turn an error into a clean message and a non-zero exit code.

## Creating a client

`HttpApiClient.make(Api, { baseUrl })` derives a client from the `Api` value.
It has one method per endpoint, grouped like the API:

- `client.rules.create({ payload })`
- `client.rules.run({ params: { id }, payload })`
- `client.runs.list({ query })`

The payload is checked against the endpoint's schema before anything is sent,
and the response is decoded with the success schema. If you change the API,
the CLI stops compiling until it agrees.

Put the client in a service, `ApiClient`, like every other dependency. Its type
is `HttpApiClient.ForApi<typeof Api>`, so you never write the shape by hand.

The client sends requests with an `HttpClient`, which is another service.
`FetchHttpClient.layer` provides one built on `fetch`.

The server's URL comes from `Config`, in three lines.
`Config.String("REFLEX_URL")` reads the environment variable, and
`Config.withDefault("http://localhost:3000")` covers the usual case. When you
`yield*` a config inside a layer, it's read when the layer is built.

## Writing the command handlers

`src/cli/main.ts` came with the starter. Every command, argument and flag is
already declared, and every handler body is empty. You write the six bodies.
Each one `yield*`s the `ApiClient`, makes one call, and prints the result.

- `rules add` reads the file with the same `readJson` as lesson 11, then calls
  `client.rules.create`.
- `rules run` and `events submit` print one outcome per line, with its reason
  or error.
- `runs list` has two optional flags. The supplied declarations hand them to
  you as `string | undefined` and `number | undefined`. That's the same shape
  the query takes, so they go straight into `client.runs.list({ query })`.

Name the handlers with `Effect.fn("rules.add")` and so on. Lesson 16 shows why
the names matter.

## Revisit: errors in the client

The 404 from lesson 14 comes back as a `RuleNotFound`. The client knows that
the endpoint declares that error, so it decodes the body into the same class
the store fails with.

Hover the `rules remove` handler. `RuleNotFound` is in its error channel, next
to the HTTP and schema errors that any request can have.

## Try it: RuleNotFound as one line

`pnpm cli rules remove nope` prints `RuleNotFound` with a stack trace into the
Schema internals. That's useful to you, but not to someone who just typed an id
wrong.

1. Write one handler with `Effect.fn` that takes the `RuleNotFound`, prints
   `No rule with id <id>` with `Console.error`, and then fails with
   `new ExitCode({ code: 1 })` from `tools/entrypoint.ts`. The command didn't
   happen, so the shell has to see a non-zero exit. `runMain` prints nothing
   more for an `ExitCode`.
2. `Effect.fn` takes more arguments after the generator, and applies each one
   to the effect it builds. Pass `Effect.catchTag("RuleNotFound", yourHandler)`
   to both the `rules remove` and `rules run` handlers.

To check your work, run `pnpm cli rules remove nope` and
`pnpm cli rules run nope --event fixtures/events/laptop.json`. Each should
print one line and exit 1 (check with `echo $?`). The hint and the changed file
are in `exercises/15/`. From lesson 16 on, the checkpoints include this change.

## Recap

- A client derived from the API can't drift from it, and it's a service like
  the rest.
- `Config` reads settings from the environment, with a default for the usual
  case.
- Errors the endpoint declares come back as the same typed classes, so you
  handle them like any other failure.
- The cost is that the CLI imports the server's domain types, so the two ship
  together.
- In lesson 16 you'll follow one command from the CLI into the server, as a
  single trace.
