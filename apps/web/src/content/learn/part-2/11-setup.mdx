So far, Reflex has lived in the browser editor. It can check expenses, but
we want to give it files to read and somewhere to save its alerts, which
means moving onto your machine. The starter includes the program from the
[Part 1 review](/learn/part-1/10-checkpoint), so we can pick up where we left
off rather than rebuild it.

This guide gets that program running locally before
[Using FileSystem and NodeRuntime.runMain](/learn/part-2/11-your-program-your-entrypoint).
It also starts a trace viewer, a separate application that will show us what
Reflex is doing once it has a server and a command-line client.

If you prefer to work through Part 1 locally, complete steps 1 and 2 now
and run each lesson with `pnpm lesson <n>`. Part 1 does not use the viewer,
so return for steps 3 and 4 after the review.

## Before you start

Allow about 15 minutes if you already have the following installed:

- Node 22.16 or newer
- pnpm, or corepack to provide it (`corepack enable`)
- git
- a browser
- for the trace viewer, one of: macOS, Linux with glibc 2.39 or newer
  (Ubuntu 24.04+, Debian 13+, Fedora 40+), or Docker

Windows through WSL2 is untested.

## 1. Get the starter

Open a terminal in the directory where you want to keep the project:

```sh
npx degit Effect-TS/website/courses/reflex reflex
cd reflex
```

`degit` copies the starter directory without the website's git history, so
the `reflex` directory is a project of your own. You can initialize a git
repository there if you want to save your changes as you go.

## 2. Install the dependencies

From inside `reflex`, install the packages the lessons use:

```sh
pnpm install
```

The Effect packages are pinned to the exact versions the lessons,
checkpoints and tests were checked against. Keep those versions while you
work through the course, so the examples match the APIs you have installed.

## 3. Check your machine and start the viewer

The starter has a script that checks for the tools we need. Run it now and
let it start the viewer as well:

```sh
pnpm run doctor --viewer
```

Include `run` in this command. pnpm has a built-in `doctor` of its own, so
`pnpm doctor` would run pnpm's checks rather than the starter's script.

On the first run, the doctor downloads otel-desktop-viewer v0.6.0 into
`.viewer/`. It reports the result of each check, then starts the viewer:

```text
Downloading https://github.com/CtrlSpice/otel-desktop-viewer/releases/download/v0.6.0/otel-desktop-viewer_linux_amd64.tar.gz
✓ node    v22.16.0
✓ pnpm    on PATH
✓ git     on PATH
✓ viewer  otel-desktop-viewer v0.6.0 in .viewer/

All set.
otel-desktop-viewer v0.6.0 (/home/you/reflex/.viewer/otel-desktop-viewer)
  UI:        http://localhost:8000
  OTLP HTTP: http://localhost:4318
Press Ctrl-C to stop.
```

Once the two localhost addresses appear, leave this terminal running,
because stopping it also stops the viewer. Open a second terminal for the
remaining commands.

If your machine cannot run the binary, for example because its Linux glibc
version is older than 2.39, the script runs the same viewer version in a
Docker container instead, and the viewer check line says so.

A line marked `✗` identifies a missing requirement and explains what to
install. Install it, then run `pnpm run doctor --viewer` again.

## 4. Run the Part 1 file

In the second terminal, in the same directory:

```sh
pnpm tsx src/run-once.ts
```

`src/run-once.ts` is the file from the Part 1 review, so the output is the
one you saw in the browser: three alert lines and three skip lines, each
prefixed with a timestamp and `INFO`:

```text
expense 1200 over 500
expense 1200 under 5000
expense 1200 over 1000
skip: missing field amount
skip: missing field amount
skip: missing field amount
```

Now open [http://localhost:8000](http://localhost:8000). The trace list is
empty, and that is expected: the viewer is ready, but Reflex does not send
it anything until
[Exporting traces with OtlpTracer](/learn/part-2/16-the-picture-you-already-know).

If the page loads and the program printed all six lines, setup is done. In
[the next lesson](/learn/part-2/11-your-program-your-entrypoint), we give
this program its first files to read. When traces start arriving,
[Reading a trace in the viewer](/learn/part-2/trace-viewer) explains what you
are looking at.

## Later sessions

You only need to download the viewer once. For later sessions:

- `pnpm viewer` starts the viewer again, without the checks.
- `pnpm run doctor` runs the checks without downloading or starting anything.
  This is the form CI uses.

## If the viewer will not start

Troubleshooting may take longer than the estimated 15 minutes. The doctor
checks the Node version, pnpm, git, and whether the viewer can run as a
binary or through Docker. If Node, pnpm or Docker are missing, you install
them yourself.

This guide does not cover proxy or firewall configuration, conflicts on
ports 8000 and 4318, or running natively on Windows. A viewer problem does
not have to hold up the lessons, though. Part 1 and the first five local
lessons work without it, and you need it from
[Exporting traces with OtlpTracer](/learn/part-2/16-the-picture-you-already-know)
on.
