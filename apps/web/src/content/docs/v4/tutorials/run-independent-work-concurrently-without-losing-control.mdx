import { TutorialCheckpoint } from "@astrojs/starlight/components"

A quote endpoint often needs several independent provider calls. `Promise.all`
makes them easy to start together, but the surrounding application must still
decide how many may run at once, how their results line up with the request,
and what stops the whole group.

In this tutorial, we will start with a familiar `node:http` endpoint backed by
Promise-based provider fixtures. We will first reproduce two concrete problems,
then move only the orchestration into Effect. The finished `POST /quotes`
endpoint will behave like this:

| Situation                                 | Observable behavior                                                               |
| ----------------------------------------- | --------------------------------------------------------------------------------- |
| Three normal line items                   | At most two line lookups run at once, while shipping overlaps with the line group |
| Lookups finish in a different order       | The response keeps the request's item order                                       |
| Line and shipping providers are both slow | One 500 ms deadline interrupts all unfinished work and returns `504`              |
| The client disconnects first              | All unfinished work is interrupted and no response is written                     |

The HTTP server will remain ordinary TypeScript throughout. Effect will manage
only the concurrent provider operation and its lifetime.

Each step ends with a checkpoint: a short verification to complete before continuing.

## 1. Start with familiar Promise concurrency

This tutorial requires Node.js 22.18.0 or newer because it runs `server.ts`
directly with Node's built-in TypeScript support.

Create an empty project:

```sh title="Create the project"
mkdir run-independent-work-concurrently
cd run-independent-work-concurrently
npm init -y
npm pkg set type=module
npm install --save-dev @types/node@22
```

Create `server.ts` with the complete file below. The bottom of the file is a
deterministic provider fixture. It uses local timers so the tutorial needs no
credentials, public network, Docker container, or second server. You will not
modify that fixture.

```ts title="server.ts" collapse={85-152}
import { createServer } from "node:http"
import { setTimeout as sleep } from "node:timers/promises"

interface OrderLine {
  readonly sku: string
  readonly quantity: number
}

interface QuoteRequest {
  readonly items: ReadonlyArray<OrderLine>
  readonly postalCode: string
}

interface QuotedLine extends OrderLine {
  readonly unitPriceCents: number
  readonly lineTotalCents: number
}

interface QuoteResponse {
  readonly currency: "EUR"
  readonly lines: ReadonlyArray<QuotedLine>
  readonly subtotalCents: number
  readonly shippingCents: number
  readonly totalCents: number
}

const buildQuote = (
  lines: ReadonlyArray<QuotedLine>,
  shippingCents: number,
): QuoteResponse => {
  const subtotalCents = lines.reduce(
    (total, line) => total + line.lineTotalCents,
    0,
  )

  return {
    currency: "EUR",
    lines,
    subtotalCents,
    shippingCents,
    totalCents: subtotalCents + shippingCents,
  }
}

const quoteOrder = async (input: QuoteRequest): Promise<QuoteResponse> => {
  const [lines, shippingCents] = await Promise.all([
    Promise.all(input.items.map((line) => quoteLine(line))),
    quoteShipping({
      postalCode: input.postalCode,
      itemCount: input.items.reduce((total, line) => total + line.quantity, 0),
    }),
  ])

  return buildQuote(lines, shippingCents)
}

const server = createServer(async (request, response) => {
  const sendJson = (status: number, body: unknown): void => {
    response.writeHead(status, { "content-type": "application/json" })
    response.end(JSON.stringify(body))
  }

  if (request.method !== "POST" || request.url !== "/quotes") {
    sendJson(404, { error: "NotFound" })
    return
  }

  try {
    let body = ""
    for await (const chunk of request) {
      body += chunk
    }
    const input = JSON.parse(body) as QuoteRequest

    const quote = await quoteOrder(input)
    sendJson(200, quote)
  } catch (cause) {
    console.error(cause)
    sendJson(500, { error: "InternalServerError" })
  }
})

server.listen(3000, () => console.log("Listening on http://localhost:3000"))

// You will not modify the code below.

const catalog: Readonly<Record<string, number>> = {
  coffee: 1250,
  tea: 700,
  cocoa: 700,
  cookies: 450,
  jam: 600,
  slow: 500,
}

const delayBySku: Readonly<Record<string, number>> = {
  coffee: 300,
  tea: 120,
  cocoa: 80,
  cookies: 180,
  jam: 240,
  slow: 1_000,
}

let activeLineLookups = 0

const quoteLine = async (
  line: OrderLine,
  { signal }: { readonly signal?: AbortSignal } = {},
): Promise<QuotedLine> => {
  activeLineLookups += 1
  console.log(`line start ${line.sku} active=${activeLineLookups}`)

  const onAbort = () => console.log(`line abort ${line.sku}`)
  signal?.addEventListener("abort", onAbort, { once: true })

  try {
    await sleep(delayBySku[line.sku] ?? 100, undefined, { signal })
    const unitPriceCents = catalog[line.sku] ?? 500
    console.log(`line finish ${line.sku}`)

    return {
      ...line,
      unitPriceCents,
      lineTotalCents: unitPriceCents * line.quantity,
    }
  } finally {
    activeLineLookups -= 1
    signal?.removeEventListener("abort", onAbort)
  }
}

const quoteShipping = async (
  input: { readonly postalCode: string; readonly itemCount: number },
  { signal }: { readonly signal?: AbortSignal } = {},
): Promise<number> => {
  console.log(`shipping start ${input.postalCode}`)

  const onAbort = () => console.log(`shipping abort ${input.postalCode}`)
  signal?.addEventListener("abort", onAbort, { once: true })

  try {
    await sleep(input.postalCode === "99999" ? 1_000 : 180, undefined, {
      signal,
    })
    console.log(`shipping finish ${input.postalCode}`)
    return 700
  } finally {
    signal?.removeEventListener("abort", onAbort)
  }
}
```

The application uses the Promise concurrency you already know. The inner
`Promise.all` starts every line lookup, while the outer `Promise.all` overlaps
the complete line group with shipping. `Promise.all` also returns line results
in input order, even when the individual Promises resolve in another order.

## 2. Reproduce the missing controls

The three-item request does not reveal how many provider calls the endpoint is
willing to open. Send a quote with five lines:

```sh title="Open five line lookups"
curl -sS http://localhost:3000/quotes \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"coffee","quantity":1},{"sku":"tea","quantity":1},{"sku":"cocoa","quantity":1},{"sku":"cookies","quantity":1},{"sku":"jam","quantity":1}],"postalCode":"00100"}' > /dev/null
```

Before any line finishes, the server logs all five starts:

```text title="Relevant server log"
line start coffee active=1
line start tea active=2
line start cocoa active=3
line start cookies active=4
line start jam active=5
```

The item count in one request currently determines the number of concurrent
line lookups. A large quote can therefore send a sudden burst to the catalog
provider. `Promise.all` preserves order, but it has no option that bounds the
concurrency of the mapped Promises.

Now ask `curl` to disconnect after 100 ms while both providers are slow:

```sh title="Disconnect during a slow quote"
curl --max-time 0.1 -sS http://localhost:3000/quotes \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"slow","quantity":1}],"postalCode":"99999"}'
```

`curl` reports that its deadline was reached and receives no response. About
one second later, the server still logs both finishes:

```text title="Relevant server log"
line start slow active=1
shipping start 99999
line finish slow
shipping finish 99999
```

The provider functions already accept an optional `AbortSignal`, a standard
Promise cancellation mechanism. The application never creates or connects one,
so the provider work outlives the HTTP client.

We could add a limiter, an `AbortController`, a timer, and cleanup code by hand.
Instead, we will let one Effect value describe the complete operation and add
those policies one at a time.

## 3. Give the complete Promise operation an Effect boundary

Keep the watched server running. In the second terminal pane, install Effect:


[`Effect.tryPromise`](/docs/v4/api/effect/Effect#tryPromise) adapts a function
that creates a Promise. Calling `quoteOrderEffect` creates a lazy description:
`quoteOrderPromise` is not called until the Effect runs. A resolved Promise
becomes a success, while a rejection enters the error channel. Effect also
supplies the `AbortSignal` that this code forwards to every provider Promise.

TypeScript infers this type for the value returned by `quoteOrderEffect`:

```ts title="Inferred type, not code to paste"
Effect.Effect<QuoteResponse, Cause.UnknownError>
```

[`Effect.Effect`](/docs/v4/api/effect/Effect#Effect) is the type of an Effect
value. Here, `QuoteResponse` is the success value. The second type argument says
that the described computation may fail with `Cause.UnknownError`.

An Effect is a value that describes a computation. Creating or transforming it
does not run the computation or perform its side effects. Effect calls the
second type parameter its error channel: it records expected failures that
callers may handle separately from successful values.

[`Cause.UnknownError`](/docs/v4/api/effect/Cause#UnknownError-interface) is
Effect's built-in wrapper for a Promise rejection that has not been classified.
Its `cause` property preserves the original rejected value. This tutorial
focuses on concurrency, so the outer HTTP `catch` will continue to turn such an
unclassified provider failure into `500`.

[`Effect.runPromise`](/docs/v4/api/effect/Effect#runPromise) runs the described
computation at the HTTP boundary and returns a Promise. That Promise resolves
with `QuoteResponse` on success and rejects if the Effect does not succeed, so
the existing TypeScript `try`/`catch` remains the final server boundary.

request. It still returns the same `200` response. Send the five-item request
as well. The active count still reaches 5 because we have changed ownership of
the operation, not its concurrency policy.

## 4. Describe each concurrent branch with Effect

The Effect boundary still hides the inner `Promise.all` calls as one opaque
Promise. Give each provider call its own Effect, then combine those descriptions
with Effect's concurrency operators. Keep the line group unbounded for this
step so behavior remains unchanged:

```ts title="server.ts" ins={46-50,61,63-74,94} collapse={1-45,77-92,96-171}

  readonly quantity: number

  readonly postalCode: string

  readonly lineTotalCents: number
}

  readonly lines: ReadonlyArray<QuotedLine>
  readonly subtotalCents: number
  readonly shippingCents: number
  readonly totalCents: number
}

const buildQuote = (
  lines: ReadonlyArray<QuotedLine>,
  shippingCents: number,
): QuoteResponse => {
  const subtotalCents = lines.reduce(
    (total, line) => total + line.lineTotalCents,
    0,
  )

  return {
    currency: "EUR",
    lines,
    subtotalCents,
    shippingCents,
    totalCents: subtotalCents + shippingCents,
  }
}

  Effect.tryPromise((signal) => quoteLine(line, { signal }))

const quoteShippingEffect = (input: QuoteRequest) =>
  Effect.tryPromise((signal) =>
    quoteShipping(
      {
        postalCode: input.postalCode,
        itemCount: input.items.reduce(
          (total, line) => total + line.quantity,
          0,
        ),
      },
      { signal },
    ),
  )

const quoteOrder = (input: QuoteRequest) =>
  Effect.all(
    [
      Effect.forEach(input.items, quoteLineEffect, {
        concurrency: "unbounded",
      }),
      quoteShippingEffect(input),
    ],
    { concurrency: "unbounded" },

    Effect.map(([lines, shippingCents]) => buildQuote(lines, shippingCents)),

const server = createServer(async (request, response) => {
```

Each provider call now uses `Effect.tryPromise` to get its own lazy Effect and
its own supplied `AbortSignal`. A resolved provider Promise becomes that
Effect's success, and a rejected Promise becomes `Cause.UnknownError` in its
error channel. This smaller scope lets the surrounding concurrency operation
interrupt every unfinished provider call.

[`Effect.forEach`](/docs/v4/api/effect/Effect#forEach) applies `quoteLineEffect`
to every request item and returns one Effect whose success is the collected
array. `concurrency: "unbounded"` lets every line lookup run at once for now.
The collected results preserve the input order, even when the calls complete in
another order.

[`Effect.all`](/docs/v4/api/effect/Effect#all) combines the line-group Effect
and shipping Effect into one Effect. `concurrency: "unbounded"` lets both
independent branches run together. Its success tuple keeps the same positions
as the input tuple: lines first and shipping cents second.

The `.pipe(...)` method passes the Effect description through transformations
from top to bottom. It composes a new description and does not run it.

[`Effect.map`](/docs/v4/api/effect/Effect#map) transforms the success channel
with a function and leaves the error channel unchanged. Here, it turns the
`[lines, shippingCents]` success tuple into the `QuoteResponse` expected by the
HTTP handler.

## 5. Bound line concurrency without losing result order

## 6. Put one deadline around the complete quote

The slow fixture still controls how long the endpoint waits. Before editing,
send a slow line and slow shipping destination without `--max-time`:

```sh title="Measure the provider-controlled wait"
curl -sS -w '\nstatus=%{http_code} time=%{time_total}s\n' \
  http://localhost:3000/quotes \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"slow","quantity":1}],"postalCode":"99999"}'
```

Both providers take about one second, so the response is `200` after about one
second. Add a single 500 ms deadline around `quoteOrder`, then turn its timeout
into an HTTP result:

```ts title="server.ts" ins={3,28-34,83-100,119-120} collapse={5-27,35-82,102-117,121-196}
import { createServer } from "node:http"
import { setTimeout as sleep } from "node:timers/promises"
import { Data, Effect } from "effect"

interface OrderLine {
  readonly sku: string
  readonly quantity: number
}

interface QuoteRequest {
  readonly items: ReadonlyArray<OrderLine>
  readonly postalCode: string
}

interface QuotedLine extends OrderLine {
  readonly unitPriceCents: number
  readonly lineTotalCents: number
}

interface QuoteResponse {
  readonly currency: "EUR"
  readonly lines: ReadonlyArray<QuotedLine>
  readonly subtotalCents: number
  readonly shippingCents: number
  readonly totalCents: number
}

interface HttpResult {
  readonly status: number
  readonly body: unknown
}

class QuoteTimedOut extends Data.TaggedError("QuoteTimedOut")<{}> {}

const buildQuote = (
  lines: ReadonlyArray<QuotedLine>,
  shippingCents: number,
): QuoteResponse => {
  const subtotalCents = lines.reduce(
    (total, line) => total + line.lineTotalCents,
    0,
  )

  return {
    currency: "EUR",
    lines,
    subtotalCents,
    shippingCents,
    totalCents: subtotalCents + shippingCents,
  }
}

const quoteLineEffect = (line: OrderLine) =>
  Effect.tryPromise((signal) => quoteLine(line, { signal }))

const quoteShippingEffect = (input: QuoteRequest) =>
  Effect.tryPromise((signal) =>
    quoteShipping(
      {
        postalCode: input.postalCode,
        itemCount: input.items.reduce(
          (total, line) => total + line.quantity,
          0,
        ),
      },
      { signal },
    ),
  )

const quoteOrder = (input: QuoteRequest) =>
  Effect.all(
    [
      Effect.forEach(input.items, quoteLineEffect, {
        concurrency: 2,
      }),
      quoteShippingEffect(input),
    ],
    { concurrency: "unbounded" },
  ).pipe(
    Effect.map(([lines, shippingCents]) => buildQuote(lines, shippingCents)),
  )

const quoteRequest = (input: QuoteRequest) =>
  quoteOrder(input).pipe(
    Effect.timeoutOrElse({
      duration: "500 millis",
      orElse: () => Effect.fail(new QuoteTimedOut()),
    }),
    Effect.map((quote): HttpResult => ({
      status: 200,
      body: quote,
    })),
    Effect.catchTag("QuoteTimedOut", () =>
      Effect.succeed({
        status: 504,
        body: { error: "QuoteTimedOut" },
      }),
    ),
  )

const server = createServer(async (request, response) => {
  const sendJson = (status: number, body: unknown): void => {
    response.writeHead(status, { "content-type": "application/json" })
    response.end(JSON.stringify(body))
  }

  if (request.method !== "POST" || request.url !== "/quotes") {
    sendJson(404, { error: "NotFound" })
    return
  }

  try {
    let body = ""
    for await (const chunk of request) {
      body += chunk
    }
    const input = JSON.parse(body) as QuoteRequest

    const result = await Effect.runPromise(quoteRequest(input))
    sendJson(result.status, result.body)
  } catch (cause) {
    console.error(cause)
    sendJson(500, { error: "InternalServerError" })
  }
})

server.listen(3000, () => console.log("Listening on http://localhost:3000"))
```

[`Data.TaggedError`](/docs/v4/api/effect/Data#TaggedError) creates the typed
`QuoteTimedOut` error class. The string passed to it becomes the instance's
`_tag`. The empty type argument means its constructor has no additional fields,
so `new QuoteTimedOut()` is the complete error value.

Effect uses `_tag` as its standard discriminator for variants. Code can inspect
that stable string without relying on an error message.

[`Effect.timeoutOrElse`](/docs/v4/api/effect/Effect#timeoutOrElse) gives the
preceding `quoteOrder` computation 500 ms. If the deadline wins, it interrupts
that complete computation before running `orElse`. Because the timeout
surrounds `Effect.all`, the same deadline covers the bounded line group and
shipping branch together.

Interruption is Effect's term for cancellation of a running computation. The
interruption reaches each provider's `AbortSignal`, which stops the underlying
timer Promise instead of leaving it active in the background.

[`Effect.fail`](/docs/v4/api/effect/Effect#fail) describes a computation that
fails through the error channel; creating it does not throw. Here, the timeout
fallback adds `QuoteTimedOut` to the error channel of `quoteRequest`.

[`Effect.catchTag`](/docs/v4/api/effect/Effect#catchTag) matches one
error-channel value by its `_tag`. The handler must return an Effect. When this
handler succeeds, `QuoteTimedOut` is handled and removed from the remaining
error channel; unclassified provider failures are not matched.

[`Effect.succeed`](/docs/v4/api/effect/Effect#succeed) describes a successful
computation with an already available value. The timeout handler uses it to
produce the `504` `HttpResult`; creating that Effect does not write the HTTP
response.

The order of the two abort lines is not significant. Both unfinished branches

## 7. Stop the quote when the client disconnects

The deadline now sends cancellation from the Effect operation to its Promise
providers. The last step connects cancellation in the other direction: an HTTP
client disconnect will stop the complete Effect operation.

Create an `AbortController` for the request, abort it if the response closes
before it was written, and pass its signal to `Effect.runPromise`:


The optional `signal` accepted by `Effect.runPromise` connects an external
`AbortSignal` to the running Effect. If the response closes first,
`controller.abort()` interrupts the complete `quoteRequest`. That interruption
then reaches the signals supplied by both `Effect.tryPromise` calls.

## Keep the application boundary ordinary

The final HTTP handler still has a TypeScript `try`/`catch`. Expected timeout
behavior has already become an `HttpResult` inside `quoteRequest`, while client
interruption is recognized by the request's `AbortController`.

If an unclassified provider rejection remains, `Effect.runPromise` rejects and
the outer `catch` returns `500`. An unexpected bug is called a defect in Effect;
it also reaches this outer boundary rather than being mislabeled as
`QuoteTimedOut`. The Effect program controls concurrency and lifetime, while
`node:http` keeps responsibility for reading and writing HTTP.
