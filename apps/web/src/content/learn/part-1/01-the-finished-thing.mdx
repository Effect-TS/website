In this course you will build reflex, a small automation engine. You write
rules as JSON, like "when an expense is over 500, send me an alert". Reflex receives events over HTTP, polls URLs on a timer,
and runs the actions of every rule that matches. It writes each run to SQLite
and records every step as a trace you can open and inspect. By the last lesson,
one of those actions sends a notification to your phone.

Before you write any code, here is where you are headed.

## A session with the finished app

This is a real terminal session with the finished app, captured from the
course's reference solution. A small local receiver on port 4600 plays the part
of the outside services your rules talk to. One rule posts to it on every
expense, and another polls its `/status` page.

Notice the `runs list` output. Every run has an outcome, and the ones that
didn't succeed say why.

You can't see it here, but the `events submit` and `rules run` commands also
leave a trace that follows the work from the CLI, into the server, and down to
the rule that ran. You'll set up the viewer that shows those traces in Part 2.

## What Part 1 builds

Part 1 builds the core of reflex in a single file: a rule, an event, and an
alert line when the rule matches. It runs entirely in your browser.

The editor already holds the file you will have at the end of Part 1, and it is
running. Open the Terminal tab under the editor. You should see:

- three alert lines for the laptop expense of 1200, one for each rule in the
  store;
- three skip lines for the taxi expense, which has no amount to compare.

Don't try to read the file yet. Each line in it arrives in a lesson of its own,
together with the problem it solves. If you'd like to poke at it anyway, change
the laptop's `amount` from `1200` to `300`. The terminal reruns the file, and
the alerts change.
