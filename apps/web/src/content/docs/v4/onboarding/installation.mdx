You need one package to start using Effect. Effect requires TypeScript 7 or newer with strict type checking enabled:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "strict": true
  }
}
```

The same package works with Node.js, Deno, Bun, and browser applications. The development tools are optional, but they become valuable as soon as the codebase grows or an AI starts editing it.

## Install Effect

Install the version used by this documentation with the command for your package manager.

<Tabs syncKey="package-manager">

<TabItem label="npm">

```sh

```

</TabItem>

<TabItem label="pnpm">


</TabItem>

<TabItem label="Yarn">

</TabItem>

The examples require a Node.js release that can run TypeScript files by stripping their types.

Create `hello.ts` with this program:

```ts
import { Effect } from "effect"

const program = Effect.succeed({
  service: "order-backend",
  status: "ready",
})

const result = await Effect.runPromise(program)

console.log(result)
```

Run it:

```sh
node hello.ts
```

You should see:

```text
{ service: 'order-backend', status: 'ready' }
```

`program` is a value that describes work. Nothing happens until `Effect.runPromise` runs it at the application boundary. Larger programs keep the same shape: build one operation, provide what it needs, and run it once.

## Install the Dev Tools

This part is recommended, not required to use Effect.

Effect's [development tools](https://github.com/Effect-TS/tsgo) add Effect-aware diagnostics, quick fixes, refactors, and type information to the normal TypeScript workflow. `@effect/tsgo` includes TypeScript-Go and the Effect language server. Use it instead of the standard `tsgo` language server, not alongside it, to avoid duplicate diagnostics.

Run the guided setup to install compatible versions and configure the project:

```sh
npx @effect/tsgo setup
```

### Install the VS Code or Cursor extension

The language server analyzes code while you edit it. The separate [Effect extension from the Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=effectful-tech.effect-vscode) adds debugger views for VS Code and Cursor. It does not install the language server, so keep `@effect/tsgo` in the project.

When execution is paused, the extension can show:

- the services available to the current computation;
- the traced operations that led to the paused line;
- the computations currently running in the background;
- unexpected failures, with an option to pause when one occurs.

The extension is also available from the [Open VSX Registry](https://open-vsx.org/extension/effectful-tech/effect-vscode).

### Run diagnostics outside the editor

The language server reports problems while you edit code. To report the same problems during automated checks, integrate it with either the TypeScript compiler or Oxlint.

<Tabs>

<TabItem label="TypeScript">

Patch the TypeScript installation used by the project:

```sh
npx effect-tsgo patch
```

Make the patch repeatable after every install and add a command for type checking:

```json title="package.json"
{
  "scripts": {
    "prepare": "effect-tsgo patch",
    "check": "tsc --noEmit"
  }
}
```

</TabItem>

<TabItem label="Oxlint">

Install the compatible packages and apply Effect's Oxlint patch:

```sh
npm install --save-dev oxlint oxlint-tsgolint
npx effect-tsgo patch --oxlint
```

Make the patch repeatable after every install:

```json
{
  "scripts": {
    "prepare": "effect-tsgo patch --oxlint",
    "lint": "oxlint ."
  }
}
```

Then create `.oxlintrc.json`:

```json
{
  "$schema": "./node_modules/@effect/tsgo/oxlint-schema.json",
  "extends": ["./node_modules/@effect/tsgo/oxlint-presets/recommended.json"]
}
```

The recommended preset enables type-aware Effect rules under the `effecttsgo/*` namespace. The patch modifies the compatible Oxlint binaries installed in your project; it is not a separate fork that you run instead of Oxlint.

</TabItem>

</Tabs>

## Check the setup

Temporarily add an Effect that is created but ignored:

```ts
import { Effect } from "effect"

const program = Effect.gen(function* () {
  Effect.log("order routes loaded")
  return "done"
})

await Effect.runPromise(program)
```

Your editor should report `effecttsgo/floating-effect` on the ignored `Effect.log` call. The same diagnostic should appear when you run `npm run check` with the TypeScript integration or `npm run lint` with the Oxlint integration.

The correction is to compose the operation into the workflow:

```ts
import { Effect } from "effect"

const program = Effect.gen(function* () {
  yield* Effect.log("order routes loaded")
  return "done"
})

await Effect.runPromise(program)
```

You now have everything required by the rest of the documentation.
