From here on, rulebook runs on your own machine, from a starter project. This
page gets that project running and starts the trace viewer, so the next lesson
can begin straight away.

In the browser track, you do this after lesson 10. If you'd rather take Part 1
locally instead of in the playground, do this setup first. Then go back to
lesson 1 and run each lesson with `pnpm lesson <n>`.

## Before the clock starts

The 15 minutes assume you already have these installed:

- Node 22.16 or newer
- pnpm, or corepack to provide it (`corepack enable`)
- git
- a browser
- for the trace viewer, one of: macOS, Linux with glibc 2.39 or newer
  (Ubuntu 24.04+, Debian 13+, Fedora 40+), or Docker

Windows through WSL2 is untested.

## 1. Get the starter

```sh
npx degit Effect-TS/website/courses/rulebook rulebook
cd rulebook
```

`degit` copies the directory without the website's git history, so `rulebook`
starts life as a fresh project of its own. Commit to it as you go if you like.

## 2. Install

```sh
pnpm install
```

The Effect packages are pinned to exact versions. They're the same versions
every lesson, checkpoint and test in the course was checked against, so what
you see should match what the lessons describe.

## 3. Check your machine and start the viewer

```sh
pnpm run doctor --viewer
```

Make sure you type the `run`. pnpm has a built-in `doctor` command of its own,
and a bare `pnpm doctor` runs that one instead of the starter's.

The first time, the doctor downloads otel-desktop-viewer v0.6.0 into
`.viewer/`. It prints one line per requirement and then starts the viewer:

```text
Downloading https://github.com/CtrlSpice/otel-desktop-viewer/releases/download/v0.6.0/otel-desktop-viewer_linux_amd64.tar.gz
✓ node    v22.16.0
✓ pnpm    on PATH
✓ git     on PATH
✓ viewer  otel-desktop-viewer v0.6.0 in .viewer/

All set.
otel-desktop-viewer v0.6.0 (/home/you/rulebook/.viewer/otel-desktop-viewer)
  UI:        http://localhost:8000
  OTLP HTTP: http://localhost:4318
Press Ctrl-C to stop.
```

Leave this terminal running, and do everything else in a second one.

If the binary can't run on your machine (Linux older than glibc 2.39, for
example), the viewer line says Docker instead, and the same version runs in a
container.

A line marked `✗` tells you what's missing and what to install. Fix it, then
run `pnpm run doctor --viewer` again.

## 4. First run

In a second terminal, in the same directory:

```sh
pnpm tsx src/run-once.ts
```

`src/run-once.ts` is the lesson 10 file. It prints the same three alert lines
and three skips you saw in the browser.

Now open [http://localhost:8000](http://localhost:8000). The viewer is running,
and its trace list is empty. That's expected. Nothing in the starter sends it
traces yet, and you'll wire that up yourself in lesson 16. If the page loads and
the three alerts printed, setup is done.
[The trace viewer](/learn/part-2/trace-viewer) explains what you'll see there
once traces arrive.

## Later sessions

You only need the doctor's download once. After that:

- `pnpm viewer` starts the viewer again, without the checks.
- `pnpm run doctor` runs the checks without downloading or starting anything.
  This is the form CI uses.

## What this page doesn't cover

Troubleshooting is outside the 15 minutes. The doctor checks the Node version,
pnpm, git, and whether the viewer can run here as a binary or through Docker.
It doesn't install Node, pnpm or Docker for you.

This course also doesn't cover proxies, firewalls, ports 8000 or 4318 already
being in use, or running natively on Windows. If the viewer won't start at all,
don't let that stop you. Part 1 and lessons 11 to 15 work without it, and you
only need it from lesson 16.
