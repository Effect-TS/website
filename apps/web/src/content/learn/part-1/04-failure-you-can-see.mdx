In reflex an amount arrives inside an **event**, a small object that says
what happened, such as `{ type: "expense", amount: 1200 }`. Events are not
always complete. A taxi receipt can arrive with a type and no amount.

There is no verdict for an expense with no amount. The program cannot check
it, and it should say so. By the end of this lesson `program` fails with a
named error when the amount is missing, and that error appears in the type of
`program`.

In this lesson you will:

- describe an event with an optional field
- define an error class with `Schema.TaggedError`
- fail an Effect with that error
- read the error type of an Effect

## 2. Define the error

Add `Schema` to the `effect` import. Then declare `MissingField` below the
interface:

<LessonCode
  file="lessons/part1/04-failure-you-can-see/solution/main.ts"
  declaration="MissingField"
/>

`Schema.TaggedError` is called twice:

- The first call, `<MissingField>()`, takes the class's own name, so the
  class can refer to its own type.
- The second call takes a **tag** and the **fields**. The tag,
  `"MissingField"`, is how you pick this error out later. The fields say what
  the error carries. This one carries the name of the missing `field`.

`Schema` gets its own lesson,
[Validating JSON with Schema](/learn/part-1/06-untrusted-json). Here it only
lists what the error carries.

## 3. Fail with the error

At the top of `program`, check for the amount. If it is missing, fail:

<LessonCode
  file="lessons/part1/04-failure-you-can-see/solution/main.ts"
  declaration="program"
/>

`return yield* new MissingField({ field: "amount" })` fails the Effect with
that error. `return` tells TypeScript that this path ends here, so after the
check `taxi.amount` is a number and the red underline is gone.

Run the file. The terminal reports a `MissingField` failure and the program
stops.

Hover `program`. The type is `Effect<string, MissingField, never>`. The
error type names the failure, so any code that uses `program` can see that it
can fail, and with what.

## Try it

An event can also be something other than an expense.

1. Declare a second error, `NotAnExpense`, the same way as `MissingField`.
2. At the top of `program`, fail with it when `taxi.type` is not
   `"expense"`.
3. Hover `program`. The error type is now `MissingField | NotAnExpense`.
   Every failure an Effect can produce joins that union.

This is practice only. The next lesson starts from the file without
`NotAnExpense`.

## What you learned

- An event is a small object that says what happened. Its fields can be
  missing.
- `Schema.TaggedError` defines an error class with a tag and typed fields.
- `return yield* new MissingField(...)` fails an Effect with that error and
  ends the current path.
- The error type of an Effect lists the failures it can produce.
- Each failure is one class. In
  [Serving an HTTP API with HttpApi](/learn/part-2/14-serve-it) these classes
  travel over HTTP, which is why they are built from `Schema`.
