A hard-coded alert isn't much use. Rulebook should look at an amount, decide
whether it's large, and only then build the message. That's a few steps in a
row:

1. decide whether `1200` is over `500`;
2. build the message;
3. log it;
4. give it back.

You could chain these with `Effect.andThen`, but nesting a call for every step
quickly gets hard to read. Effect has a way to write them one per line.

You will learn:

- how to write effectful steps in order with `Effect.gen`;
- what `yield*` does, and when you need it;
- what happens when you forget it.

## Writing steps with Effect.gen

`Effect.gen` lets you write effects one after another, the way you'd write
ordinary code:

```ts
Effect.gen(function* () {
  // one step per line
})
```

Inside the block, `yield*` runs an effect and hands you its result before
moving on to the next line. Whatever you `return` becomes what the whole
effect gives back, so it is what you'll see in the first slot of its type.

The `function*` makes this a generator function. That's all you need to know
about generators for this course. Read `yield*` as "run this effect here".

## Calling plain functions

Not everything has to be an effect. Deciding whether an amount is large is a
plain question with a plain answer, so write it as a plain function:
`isLarge(amount)` returns `amount > 500`. You call it like any function,
without `yield*`. Save `yield*` for effects.

Now replace the file's `alert` and `program` with:

1. a constant, `const amount: number = 1200`;
2. `isLarge`, as above;
3. a `program` built with `Effect.gen` that builds the message from `amount`
   (`expense 1200 over 500` when it's large, `expense 1200: no alert` when it
   isn't), `yield*`s the log, and returns the message.

The terminal prints the alert line once. Hover `program`. The first slot now
says `string`, because the block returns the message.

## Try it: forget a yield\*

Delete the `yield*` in front of `Effect.log(message)` and hover that
expression. You're holding an `Effect<void>`, a description, not a log line,
and nothing runs it. The line disappears from the terminal.

TypeScript doesn't complain. This is the cost of descriptions from lesson 2: an
effect you build inside a generator and forget to `yield*` is quietly dropped.
When a log line or a step goes missing, a missing `yield*` is the first thing
to look for.

Put the `yield*` back before you move on.

## Recap

- `Effect.gen` runs effects in order, one per line.
- `yield*` runs an effect and hands you its result. What you `return` is what
  the whole effect gives back.
- Plain functions, like `isLarge`, stay plain, with no `yield*`.
- Every effectful line needs a `yield*`, and a line without one is dropped
  without a word.
- In lesson 7 you'll give a generator a name, so its failures say where they
  came from.

## Checkpoint

The message is built from `amount` and logged once. Hover `program`, and the
first slot shows `string`.
