Printing the same alert twice proves that you can reuse an Effect. Now give
reflex two expenses to check: a laptop at 1200 and a lunch at 40. It should
log whether each expense is over 500, then report how many were flagged.

The summary depends on the results of both checks, so those results must be
available before it runs. `Effect.gen` lets you write that sequence in a
form that resembles ordinary TypeScript, using the result of each Effect
in the lines that follow.

The completed program will print `expense 1200 over 500`,
`expense 40: no alert` and `1 of 2 expenses flagged`, in that order.

## Checking one expense with Effect.gen

Below `isLarge`, add `evaluate`. It checks one amount, logs the verdict and
reports whether the amount was flagged:

<LessonCode
  file="lessons/part1/03-steps-in-order/solution/main.ts"
  declaration="evaluate"
/>

`Effect.gen(function*() { ... })` builds an Effect from a generator function.
You do not need to study generators separately to use this pattern. Inside
the function, write ordinary calculations as usual and use `yield*` when
you need to run an Effect.

When this Effect runs, it first calls `isLarge(amount)` and stores the
boolean in `flagged`. Then `yield* Effect.log(...)` runs the logging Effect
and waits for it to finish. Finally, `return flagged` makes that boolean
the result of the whole Effect.

Hover `evaluate`. Its type is
`(amount: number) => Effect<boolean, never, never>`. Calling `evaluate(1200)`
does not log anything yet. It returns an Effect whose success type is
`boolean`, inferred from the value returned by the generator. The
generator body runs only when that Effect runs.

## Using the results in the summary

Delete `alert` and replace `program` with a second `Effect.gen` block:

Inside this generator, `yield* evaluate(1200)` runs the laptop check and
assigns its result to `laptop`. Hover `laptop` to confirm that it is a
`boolean`, not an Effect. The lunch check runs next, using the same pattern.

Both results are now ordinary booleans, so the third line can count them
with plain TypeScript. `filter(Boolean)` keeps the `true` values, and
`length` counts them.

Run the file. The terminal prints the laptop's verdict, then the lunch's,
then `1 of 2 expenses flagged`. The summary comes last because each `yield*`
finishes before the next line starts.

Hover `program`. The type is `Effect<void, never, never>`. Its generator
has no return value, so the success type is `void`.

## Try it

Omitting `yield*` is an easy mistake to make. Try it deliberately so you
can recognize the symptoms:

1. Delete the `yield*` in front of `evaluate(40)`.
2. Look for a red underline. There is none, and the playground reports no
   errors. Leaving out `yield*` is valid TypeScript.
3. Hover `lunch`. It is now `Effect<boolean, never, never>` instead of
   `boolean`. The changed type reveals the mistake even though TypeScript
   accepts the code.
4. Run the file. The terminal prints `expense 1200 over 500`, then
   `2 of 2 expenses flagged`. The line for 40 is missing, because nothing ran
   that Effect. The summary is wrong, because `lunch` is an Effect, which is
   an object, and `filter(Boolean)` keeps every object.
5. Put the `yield*` back and run the file again. The three lines return.

When a log line goes missing or a result looks wrong, check for a missing
`yield*` first.

Later, in [Naming steps with Effect.fn](/learn/part-1/07-name-it-see-it),
you will turn `evaluate` into a named Effect function so you can identify
it in failure reports. For now, keep the `Effect.gen` version.
