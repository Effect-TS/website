To check the last lesson you ran `main.ts`, read the printed run log, and
opened `alerts.log`. That works once. It does not work after every change,
and it writes a real file each time. In this lesson you write the first tests
for the stores and the Engine. They run in a second and touch nothing on
disk.

In this lesson you will:

- write a test that runs an Effect with `it.effect`
- give every test a fresh set of services with `layer()`
- assert on a failure you expect with `Effect.flip`
- swap in a fake file system

## 1. Write the first test

The starter uses `@effect/vitest`, which is vitest with Effect support. Tests
live in `test/`, next to `src/`, and `pnpm test` runs them. Three pieces from
that package do most of the work:

- `it.effect("name", () => effect)` runs an Effect as a test. The test passes
  when the effect succeeds and fails when it fails.
- `layer(SomeLayer)("name", (it) => { ... })` builds the layer and provides it
  to every `it.effect` inside. With `{ buildPerTest: true }`, each test gets a
  fresh build, so one test's rules never leak into the next.
- `assert` has the usual checks: `strictEqual`, `deepStrictEqual`, `match`,
  `isNull`.

Create `test/RuleStore.test.ts`. Provide `RuleStore.layerMemory` and write a
test that stores two rules, then lists, gets and removes them:

<LessonCode file="checkpoints/13/test/RuleStore.test.ts" />

```sh
pnpm test test/RuleStore.test.ts
```

The first test is green. The memory store starts empty for every test, which
is what makes this cheap.

## 2. Assert on a failure you expect

Getting an id that does not exist should fail with `RuleNotFound`. Write that
test the direct way first: `const error = yield* store.get("missing")`, then
assert on `error`.

Run `pnpm test test/RuleStore.test.ts`. The test is red, and vitest prints a
`RuleNotFound` with `id: "missing"`.

The store did the right thing. The test is wrong: it treats the failure you
expected as a failure of the test.

`Effect.flip` swaps the success type and the error type. The failure becomes
the success, so `yield* Effect.flip(store.get("missing"))` gives you the
`RuleNotFound` to assert on. If the store returned a rule instead, the test
would fail. Wrap the call, run the test again, and it is green. The second
and third tests in the file above do this.

You saw the test fail before you saw it pass. A test you have only seen green
has not shown that it can see anything.

## 3. Swap in a fake file system

The Engine needs a `FileSystem`, and a test should not write `alerts.log`.

`FileSystem.layerNoop` builds a file system where every method does nothing
and fails, except the ones you pass in. Keep a `writes` array in the test
file and pass `writeFileString: (path) => Effect.sync(() => writes.push(path))`,
and the same for `writeFile`. Every append the Engine makes lands in the
array, and the test asserts what was written without a file ever existing.

The Engine's test layer is `Engine.layer` with `RuleStore.layerMemory`,
`RunLog.layerMemory` and the recording file system. It is the same three-part
build as `main.ts`, with one piece swapped, and `Engine.ts` does not change.
You made this move in
[Providing a service with a layer](/learn/part-1/09-provide-it) by changing
one line. This time the reason is tests.

The reference solution uses `FileSystem.makeNoop`, which gives you the same
file system as a plain value that you wrap in `Layer.succeed` yourself.

## Try it

A missing field is `skipped`, not `failed`. Write the test that says so.
Assert it on the run rows, not only on what `handleEvent` returns. The rows
are what `runs list` will show and what a later lesson stores in SQLite.

1. In `test/Engine.test.ts`, build the test layer from step 3. Store a rule
   with the `amount gt 500` condition, submit
   `{ type: "expense", description: "no amount" }`, and read the rows with
   `RunLog.list()`. Assert exactly one row, `skipped`, with a `reason` that
   matches `/amount/`, an `error` that is null, and no writes.
2. Run `pnpm test test/Engine.test.ts`. It is green.
3. Plant a bug. Change the `MissingField` catch in `src/Engine.ts` to
   `reason: "no match"`. `pnpm check` still passes, because the row is
   well-typed. Run the test. It is red:
   `expected 'no match' to match /amount/`.
4. Put `` `missing field ${error.field}` `` back. Green again.

The test filter also matches `checkpoints/13/test/Engine.test.ts`, the
reference tests. They test the checkpoint, not your `src/`, so they stay
green throughout. The hint and the test are in `exercises/13/`.

## What you learned

- An `it.effect` test is an Effect, and `layer()` provides what it needs.
- `Effect.flip` lets you assert on a failure you expect.
- A fake service is a layer like any other. Swapping it in does not change the
  code under test.
- The cost is keeping fakes accurate. The recording file system only knows the
  two methods you gave it.
- In [Storing data in SQLite with SqlClient](/learn/part-3/17-survive-a-restart)
  these same suites run against SQLite.
