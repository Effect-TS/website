Thrown errors work, but they leave a question unanswered: when you call a
function, **what can fail**?

This tutorial shows how `Effect` makes those failures part of a function's return type,
so each one is visible at runtime _and_ in the signature, where the type checker tracks it.

You're going to use one operation throughout the tutorial: load a user profile from an HTTP
API, validate the response, and save it. That operation can fail five ways:

- The network drops.
- The body fails to parse.
- The profile is missing.
- The server denies access.
- The save conflicts with an existing record.

Keep those five in mind, because making them visible is the whole point.

## Shape the failure surface

Here is a common version of the load step without `Effect`, using try/catch and thrown errors: four named error classes, a type guard, and a try around each await.

```ts twoslash title="loadProfile.ts"
interface Profile {
  readonly id: string
  readonly name: string
  readonly email: string
}

class NetworkError extends Error {
  constructor(cause?: unknown) {
    super("The request never completed", { cause })
  }
}
class ProfileNotFound extends Error {
  constructor(readonly id: string) {
    super(`No profile for ${id}`)
  }
}
class Forbidden extends Error {
  constructor(readonly id: string) {
    super(`Not allowed to see ${id}`)
  }
}
class ParseError extends Error {
  constructor(cause?: unknown) {
    super("The body is not a profile", { cause })
  }
}

function isProfile(body: unknown): body is Profile {
  const p = body as Profile
  return (
    typeof p?.id === "string" &&
    typeof p?.name === "string" &&
    typeof p?.email === "string"
  )
}

async function loadProfile(id: string): Promise<Profile> {
  let response: Response
  try {
    response = await fetch(`/api/profiles/${id}`, {
      headers: { Accept: "application/json" },
    })
  } catch (cause) {
    throw new NetworkError(cause)
  }

  if (!response.ok) {
    if (response.status === 404) throw new ProfileNotFound(id)
    if (response.status === 403) throw new Forbidden(id)
    throw new NetworkError(`Request failed: ${response.status}`)
  }

  let body: unknown
  try {
    body = await response.json()
  } catch (cause) {
    throw new ParseError(cause)
  }

  if (!isProfile(body)) throw new ParseError()
  return body
}
```

Nothing in that code tells you what can go wrong. TypeScript has no syntax for
it: `Promise` says nothing about failure.

`loadProfile` is a common function signature that hides how it can fail:

{/* prettier-ignore */}
```ts showLineNumbers=false
//                   ┌─── Needs `id`
//                   │                    ┌─── Returns `Profile`
//                   ▼                    ▼
function loadProfile(id: string): Promise<Profile> // <- How can it fail?
```

To find out, you have to read the implementation, or the docs if they exist and
haven't drifted from it. Either way, the signature never shows it.

Worse, the compiler can't tell you any of this. Suppose a caller tries to handle
the failure:

```ts showLineNumbers=false
try {
  const profile = await loadProfile("123")
} catch (error) {
  // error: unknown
  if (error instanceof Forbidden) {
    // ...
  }
}
```

Every one of these still compiles:

1. `error` is `unknown`: the compiler cannot see which errors `loadProfile`
   throws.
1. `error instanceof Forbidden` compiles even if `loadProfile`
   never throws it.
1. Forgetting a class that `loadProfile` does throw still compiles.
1. Adding a new thrown error inside `loadProfile` later: every caller still
   compiles, and the failure reaches production.

A **good function signature** is a contract with three clauses:

1. what the function needs
1. what it returns on success
1. how it can fail

**Meet `Effect`**, which satisfies all three clauses and makes the contract explicit:

{/* prettier-ignore */}
```ts showLineNumbers=false
//                   ┌─ What the function needs
//                   │                   ┌─ What it returns on success
//                   │                   │        ┌─ How it can fail
//                   ▼                   ▼        ▼
function loadProfile(id: string): Effect<Profile, ProfileNotFound | Forbidden | NetworkError | ParseError>
```

An `Effect<Success, Error>` is a description of a program with both a `Success` and an `Error` type parameter:

| Type parameter | Clause                     |
| -------------- | -------------------------- |
| `Success`      | what it returns on success |
| `Error`        | how it can fail            |

All possible failures in an `Effect`'s `Error` type parameter are exposed as a union type.

Now `loadProfile`'s signature can be read as:

- **needs** an id.
- **succeeds** with a `Profile`.
- **fails** with a `ProfileNotFound`, or `Forbidden`, or `NetworkError`, or `ParseError`.

<Aside type="note" title="Checkpoint">
  You can now read a signature as a contract with three clauses: what the
  function needs, what it returns on success, and how it can fail. A `Promise`
  declares the first two, so the third lives only in the implementation. An
  `Effect` signature declares all three, and its `Error` type parameter is the
  complete list of ways the function can fail.
</Aside>

## Model failures as values

The `Error` type parameter lists the failures. Now build the values that go in
it.

Return each failure instead of throwing it:

- A thrown error becomes `unknown` in a `catch`, so the compiler loses it.
- A returned value keeps its type, so the compiler tracks it through every caller.

`Effect` uses two conventions for these values:

- an `Error` suffix on the class, to tell a failure from a success at a glance.
- a `_tag` property, unique to each failure, so the compiler can tell them apart.

`Data.TaggedError` builds both. Its argument becomes the `_tag`:

{/* prettier-ignore */}
```ts import.meta.vitest showLineNumbers=false mark=/class \w+(Error)|TaggedError[(](.CustomError.)[)]/
import { Data } from "effect"

//          ┌─ `Error` suffix
//          │                               ┌─ `_tag` property value
//          ▼                               ▼
class CustomError extends Data.TaggedError("CustomError") {}

const error = new CustomError()
error._tag // => "CustomError"
```

<Aside type="tip" title="Why use a class?">
  In TypeScript a class is both a type _and_ a value. One declaration gives you
  the failure type to name in a signature and the constructor to build it, with
  no extra imports.
</Aside>

Refactor the four error classes to `Data.TaggedError`:

```ts twoslash import.meta.vitest collapse={3-7,25-59} title="loadProfile.ts"
import { Data } from "effect"

interface Profile {
  readonly id: string
  readonly name: string
  readonly email: string
}

class NetworkError extends Data.TaggedError("NetworkError")<{
  readonly cause?: unknown
}> {}

class ProfileNotFoundError extends Data.TaggedError("ProfileNotFoundError")<{
  readonly id: string
}> {}

class ForbiddenError extends Data.TaggedError("ForbiddenError")<{
  readonly id: string
}> {}

class ParseError extends Data.TaggedError("ParseError")<{
  readonly cause?: unknown
}> {}

function isProfile(body: unknown): body is Profile {
  const p = body as Profile
  return (
    typeof p?.id === "string" &&
    typeof p?.name === "string" &&
    typeof p?.email === "string"
  )
}

async function loadProfile(id: string): Promise<Profile> {
  let response: Response
  try {
    response = await fetch(`/api/profiles/${id}`, {
      headers: { Accept: "application/json" },
    })
  } catch (cause) {
    throw new NetworkError({ cause })
  }

  if (!response.ok) {
    if (response.status === 404) throw new ProfileNotFoundError({ id })
    if (response.status === 403) throw new ForbiddenError({ id })
    throw new NetworkError({})
  }

  let body: unknown
  try {
    body = await response.json()
  } catch (cause) {
    throw new ParseError({ cause })
  }

  if (!isProfile(body)) throw new ParseError({})
  return body
}

// four distinct failures, each with its own `_tag`
new NetworkError({})._tag // => "NetworkError"
new ProfileNotFoundError({ id: "123" })._tag // => "ProfileNotFoundError"
new ForbiddenError({ id: "123" })._tag // => "ForbiddenError"
new ParseError({})._tag // => "ParseError"
```

The `{ ... }` after each `TaggedError` declares the fields' shape a failure
carries.

<Aside type="note" title="Some failures renamed">
  `ProfileNotFound` and `Forbidden` from the first version become
  `ProfileNotFoundError` and `ForbiddenError` here, to follow the `Error`-suffix
  convention.
</Aside>

<Aside type="note" title="Checkpoint">
  You now model each failure as a value: a class from `Data.TaggedError`, with
  an `Error` suffix and a `_tag` that tells it apart from the others. These
  values are the members of an `Effect`'s `Error` union.
</Aside>
