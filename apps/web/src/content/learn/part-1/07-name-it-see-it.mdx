The malformed rule fails, as it should. Now look at the failure in the
terminal more closely. It says _what_ went wrong, a `SchemaError` at `["op"]`,
but not which part of your program it came from. With one function you can
guess. A real program has dozens of steps, and a failure that doesn't say
where it happened sends you hunting.

You will learn:

- how to give an effectful function a name with `Effect.fn`;
- what a span is;
- how to find that name in a failure.

## Using Effect.fn

`Effect.fn("evaluate")` is `Effect.gen` with a name. Today `evaluate` is an
arrow function that returns `Effect.gen(function*() { ... })`. Rewrite it so
the parameters move onto the generator:

```ts
Effect.fn("evaluate")(function* (json: string, event: Event) {
  // the same steps as before
})
```

Anything you pass after the generator is applied to the result, the same way
`.pipe` would apply it. So the `catchTag` moves there, as a second argument.

## Spans

Every call to `evaluate` now runs inside a **span** named `evaluate`. A span is
a record of one piece of work: its name, when it started, how long it took, and
whether it succeeded.

You won't see spans drawn as a timeline yet. That needs a trace viewer, and
you'll connect one in lesson 16. But the name is already useful. When an effect
fails inside a span, the failure that `runMain` prints says which span it was
in.

## Reading the name in a failure

Look at the malformed rule's failure in the terminal again. Under the
`SchemaError` there's now a line that starts with `at evaluate (`. That's the
name you passed to `Effect.fn`, telling you the failure happened inside
`evaluate`. The line after it, `at evaluate (definition)`, points at where you
declared the function.

Before this lesson, the failure had neither line. Nothing else about the
program changed: the laptop still alerts and the taxi is still skipped.

## Try it: name the decode too

The failure says it happened inside `evaluate`, but `evaluate` does several
things. Which step failed?

Give the decode its own name. Turn `decodeRule` into a function made with
`Effect.fn("decodeRule")` that takes the JSON string and decodes it. Run the
file again and read the failure. It now names both steps, `at decodeRule`
first and `at evaluate` under it. That reads like a path: the decode failed,
and it was running inside `evaluate`.

## Recap

- `Effect.fn("name")` names a function and runs every call inside a span with
  that name.
- A span records one piece of work: when it started, how long it took, and
  whether it succeeded.
- When a call fails, the failure names the spans it was in, as
  `at evaluate (…)`.
- Spans aren't free. Each one costs a little time and, once exported, some
  traffic. Name the steps whose boundaries you want to see, not every helper.
  That's why `matches` stays a plain function.
- In lesson 16 you'll send spans to a trace viewer, and see their durations
  and how they nest. The names you choose now are the names you'll read there.

## Checkpoint

The laptop alerts, the taxi is skipped, and the malformed rule's failure shows
the `SchemaError` with an `at evaluate (…)` line naming the step it failed in.
