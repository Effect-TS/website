A quote endpoint often needs several independent provider calls. `Promise.all`
makes them easy to start together, but the surrounding application must still
decide how many may run at once, how their results line up with the request,
and what stops the whole group.

In this tutorial, we will start with a familiar `node:http` endpoint backed by
Promise-based provider fixtures. We will first reproduce two concrete problems,
then move only the orchestration into Effect. The finished `POST /quotes`
endpoint will behave like this:

| Situation                                 | Observable behavior                                                               |
| ----------------------------------------- | --------------------------------------------------------------------------------- |
| Three normal line items                   | At most two line lookups run at once, while shipping overlaps with the line group |
| Lookups finish in a different order       | The response keeps the request's item order                                       |
| Line and shipping providers are both slow | One 500 ms deadline interrupts all unfinished work and returns `504`              |
| The client disconnects first              | All unfinished work is interrupted and no response is written                     |

The HTTP server will remain ordinary TypeScript throughout. Effect will manage
only the concurrent provider operation and its lifetime.

import { createServer } from "node:http"
import { setTimeout as sleep } from "node:timers/promises"

interface OrderLine {
  readonly sku: string
  readonly quantity: number
}

interface QuoteRequest {
  readonly items: ReadonlyArray<OrderLine>
  readonly postalCode: string
}

interface QuotedLine extends OrderLine {
  readonly unitPriceCents: number
  readonly lineTotalCents: number
}

interface QuoteResponse {
  readonly currency: "EUR"
  readonly lines: ReadonlyArray<QuotedLine>
  readonly subtotalCents: number
  readonly shippingCents: number
  readonly totalCents: number
}

const buildQuote = (
  lines: ReadonlyArray<QuotedLine>,
  shippingCents: number,
): QuoteResponse => {
  const subtotalCents = lines.reduce(
    (total, line) => total + line.lineTotalCents,
    0,
  )

  return {
    currency: "EUR",
    lines,
    subtotalCents,
    shippingCents,
    totalCents: subtotalCents + shippingCents,
  }
}

const quoteOrder = async (input: QuoteRequest): Promise<QuoteResponse> => {
  const [lines, shippingCents] = await Promise.all([
    Promise.all(input.items.map((line) => quoteLine(line))),
    quoteShipping({
      postalCode: input.postalCode,
      itemCount: input.items.reduce((total, line) => total + line.quantity, 0),
    }),
  ])

  return buildQuote(lines, shippingCents)
}

const server = createServer(async (request, response) => {
  const sendJson = (status: number, body: unknown): void => {
    response.writeHead(status, { "content-type": "application/json" })
    response.end(JSON.stringify(body))
  }

  if (request.method !== "POST" || request.url !== "/quotes") {
    sendJson(404, { error: "NotFound" })
    return
  }

  try {
    let body = ""
    for await (const chunk of request) {
      body += chunk
    }
    const input = JSON.parse(body) as QuoteRequest

    const quote = await quoteOrder(input)
    sendJson(200, quote)
  } catch (cause) {
    console.error(cause)
    sendJson(500, { error: "InternalServerError" })
  }
})

server.listen(3000, () => console.log("Listening on http://localhost:3000"))

const catalog: Readonly<Record<string, number>> = {
  coffee: 1250,
  tea: 700,
  cocoa: 700,
  cookies: 450,
  jam: 600,
  slow: 500,
}

const delayBySku: Readonly<Record<string, number>> = {
  coffee: 300,
  tea: 120,
  cocoa: 80,
  cookies: 180,
  jam: 240,
  slow: 1_000,
}

let activeLineLookups = 0

const quoteLine = async (
  line: OrderLine,
  { signal }: { readonly signal?: AbortSignal } = {},
): Promise<QuotedLine> => {
  activeLineLookups += 1
  console.log(`line start ${line.sku} active=${activeLineLookups}`)

  const onAbort = () => console.log(`line abort ${line.sku}`)
  signal?.addEventListener("abort", onAbort, { once: true })

  try {
    await sleep(delayBySku[line.sku] ?? 100, undefined, { signal })
    const unitPriceCents = catalog[line.sku] ?? 500
    console.log(`line finish ${line.sku}`)

    return {
      ...line,
      unitPriceCents,
      lineTotalCents: unitPriceCents * line.quantity,
    }
  } finally {
    activeLineLookups -= 1
    signal?.removeEventListener("abort", onAbort)
  }
}

const quoteShipping = async (
  input: { readonly postalCode: string; readonly itemCount: number },
  { signal }: { readonly signal?: AbortSignal } = {},
): Promise<number> => {
  console.log(`shipping start ${input.postalCode}`)

  const onAbort = () => console.log(`shipping abort ${input.postalCode}`)
  signal?.addEventListener("abort", onAbort, { once: true })

  try {
    await sleep(input.postalCode === "99999" ? 1_000 : 180, undefined, {
      signal,
    })
    console.log(`shipping finish ${input.postalCode}`)
    return 700
  } finally {
    signal?.removeEventListener("abort", onAbort)
  }
}

## 2. Reproduce the missing controls

The three-item request does not reveal how many provider calls the endpoint is
willing to open. Send a quote with five lines:

```sh title="Open five line lookups"
curl -sS http://localhost:3000/quotes \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"coffee","quantity":1},{"sku":"tea","quantity":1},{"sku":"cocoa","quantity":1},{"sku":"cookies","quantity":1},{"sku":"jam","quantity":1}],"postalCode":"00100"}' > /dev/null
```

Before any line finishes, the server logs all five starts:

```text title="Relevant server log"
line start coffee active=1
line start tea active=2
line start cocoa active=3
line start cookies active=4
line start jam active=5
```

The item count in one request currently determines the number of concurrent
line lookups. A large quote can therefore send a sudden burst to the catalog
provider. `Promise.all` preserves order, but it has no option that bounds the
concurrency of the mapped Promises.

Now ask `curl` to disconnect after 100 ms while both providers are slow:

```sh title="Disconnect during a slow quote"
curl --max-time 0.1 -sS http://localhost:3000/quotes \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"slow","quantity":1}],"postalCode":"99999"}'
```

`curl` reports that its deadline was reached and receives no response. About
one second later, the server still logs both finishes:

```text title="Relevant server log"
line start slow active=1
shipping start 99999
line finish slow
shipping finish 99999
```

The provider functions already accept an optional `AbortSignal`, a standard
Promise cancellation mechanism. The application never creates or connects one,
so the provider work outlives the HTTP client.

We could add a limiter, an `AbortController`, a timer, and cleanup code by hand.
Instead, we will let one Effect value describe the complete operation and add
those policies one at a time.

<EffectApi
  name="Effect.tryPromise"
  href="/docs/v4/api/effect/Effect#tryPromise"
>
  Adapts a function that creates a Promise. Calling `quoteOrderEffect` creates a
  lazy description: `quoteOrderPromise` is not called until the Effect runs. A
  resolved Promise becomes a success, while a rejection enters the error
  channel. Effect also supplies the `AbortSignal` that this code forwards to
  every provider Promise.
</EffectApi>

TypeScript infers this type for the value returned by `quoteOrderEffect`:

```ts title="Inferred type, not code to paste"
Effect.Effect<QuoteResponse, Cause.UnknownError>
```

<EffectApi name="Effect.Effect" href="/docs/v4/api/effect/Effect#Effect">
  The type of an Effect value. Here, `QuoteResponse` is the success value. The
  second type argument says that the described computation may fail with
  `Cause.UnknownError`.
</EffectApi>

An Effect is a value that describes a computation. Creating or transforming it
does not run the computation or perform its side effects. Effect calls the
second type parameter its error channel: it records expected failures that
callers may handle separately from successful values.

<EffectApi
  name="Cause.UnknownError"
  href="/docs/v4/api/effect/Cause#UnknownError-interface"
>
  Effect's built-in wrapper for a Promise rejection that has not been
  classified. Its `cause` property preserves the original rejected value. This
  tutorial focuses on concurrency, so the outer HTTP `catch` will continue to
  turn such an unclassified provider failure into `500`.
</EffectApi>

<EffectApi
  name="Effect.runPromise"
  href="/docs/v4/api/effect/Effect#runPromise"
>
  Runs the described computation at the HTTP boundary and returns a Promise.
  That Promise resolves with `QuoteResponse` on success and rejects if the
  Effect does not succeed, so the existing TypeScript `try`/`catch` remains the
  final server boundary.
</EffectApi>

The deadline now sends cancellation from the Effect operation to its Promise
providers. The last step connects cancellation in the other direction: an HTTP
client disconnect will stop the complete Effect operation.

## Keep the application boundary ordinary

The final HTTP handler still has a TypeScript `try`/`catch`. Expected timeout
behavior has already become an `HttpResult` inside `quoteRequest`, while client
interruption is recognized by the request's `AbortController`.

If an unclassified provider rejection remains, `Effect.runPromise` rejects and
the outer `catch` returns `500`. An unexpected bug is called a defect in Effect;
it also reaches this outer boundary rather than being mislabeled as
`QuoteTimedOut`. The Effect program controls concurrency and lifetime, while
`node:http` keeps responsibility for reading and writing HTTP.
