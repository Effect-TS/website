Welcome to Learn Effect. In this tutorial, we'll build reflex, a small
application for automating things you'd otherwise have to check yourself.
Perhaps you want to notice an unusually large expense, or get a notification
when a service you rely on goes down. Reflex will let you describe a rule
for each of those situations and choose what should happen when it matches.

We'll start with expenses. Imagine keeping a record of your purchases and
wanting an alert whenever one costs more than 500. A laptop would be worth
a look; lunch probably wouldn't. By the end of the course, you'll be able
to submit those expenses to a running server, inspect a history of its
decisions, and even send an alert to your phone.

There are quite a few things to learn along the way, but you don't need to
build all of that at once. We'll grow the same application a little at a
time, introducing Effect as we need it. If you're comfortable reading
TypeScript, you have enough background to begin. You don't need any prior
Effect experience, and there's nothing to install for this first part:
the editor on this page runs the program in your browser.

For our first step, let's make an alert appear. We won't check an expense
or send a notification yet. Writing a message to the terminal is enough to
see how an Effect program runs.

## Your first alert

Find `program` in the editor. It contains the message for our example
laptop purchase:

Run the file. You should see a log line containing
`expense 1200 over 500` in the terminal. That means the laptop cost 1200,
which is over our limit of 500. For now, the message is written directly
in the code; in the next lesson we'll work it out from the amount.

There are two lines involved in producing this output. The
`Effect.log(...)` call creates a value that describes writing the message.
We call that value an **Effect**, and store it in `program`. The last line,
`NodeRuntime.runMain(program)`, runs it.

That separation is the first thing to get used to. Calling `Effect.log`
doesn't print anything on its own. It gives us something we can run later,
or combine with other work before running it. Let's try that now.

## Try running the alert twice

We'll reuse the alert to make a program that logs the same message twice.
Leave the `NodeRuntime.runMain(program)` line as it is and change the code
above it:

1. Rename the existing `program` constant to `alert`.
2. Add a new `program` constant set to `Effect.andThen(alert, alert)`.
   `Effect.andThen(first, second)` runs `first`, then `second` when the
   combined Effect runs.
3. Run the file again. This time, the terminal should contain two copies
   of the message.

The alert itself hasn't changed. You've used it twice in a larger
program, and the same run line still runs the whole thing. As reflex grows,
we'll use this approach to put together work such as reading a file,
checking an expense and writing the result.

## A first look at the type

Before moving on, hover over `program`. The editor shows
`Effect<void, never, never>`. You don't need to learn all of that notation
yet. Start with `void`: logging writes a message, but it doesn't produce a
result for the next step to use. We call this the Effect's **success type**.
Running the alert twice still leaves us with `void`.

You can leave the two `never` parameters alone for now. They describe
errors and requirements, which we'll introduce when the program needs
them. There's no need to understand the whole type to run this alert.

You now have an alert you can reuse and a program that runs it. Next,
[we'll give reflex two expenses to check](/learn/part-1/03-steps-in-order)
so it can decide which one deserves an alert, rather than printing the
same message every time.
