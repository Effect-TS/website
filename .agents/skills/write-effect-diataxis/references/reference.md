# Reference

Write an accurate, concise description of Effect's machinery for a reader who
needs facts while working.

## Follow the machinery

- Organize the page around the structure of the API, type, module, protocol, or
  configuration being described.
- Use predictable headings and repeated field order so facts are easy to scan.
- Cover the declared scope completely. Do not substitute representative
  examples for missing facts.
- State types, inputs, outputs, errors, requirements, defaults, constraints,
  interruption behavior, and stability when relevant.
- Verify every claim against the installed package or the authoritative
  generated source.

## Describe without teaching or persuading

- Use neutral, factual language.
- Keep examples short and illustrative. They demonstrate a fact but do not
  become a guided project.
- Do not lead with a pain point, prescribe a user journey, or discuss broad
  rationale inside the factual description.
- Link to tutorials for learning, how-to guides for tasks, and explanation for
  concepts or design reasoning.

## Review the reference

Verify that readers can predict where a fact will appear, distinguish similar
operations, and obtain a precise answer without reconstructing it from prose or
examples.
