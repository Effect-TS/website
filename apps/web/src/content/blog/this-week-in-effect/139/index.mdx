Welcome back to This Week in Effect, your weekly update of the latest developments in the Effect community and ecosystem.

Effect is the TypeScript library for the AI era, helping developers build complex, synchronous, and asynchronous programs. One key feature that sets Effect apart is how it leverages structured concurrency to provide features such as async cancellation and safe resource management, making it easier to build robust, scalable, and efficient programs.

### Effect v4 updates.

It has been a week since Effect 4.0 shipped, and the pace has not slowed. According to [Sebastian's post on the first week](https://effect.website/blog/effect-4-first-week), almost 30 contributors landed around 150 commits on `main`, and two patch releases went out: 4.0.1 on October 5 and 4.0.2 on October 8. Here are the most notable changes.

- **Stability tags**: Every module and importable export now declares its `@stability` level explicitly, enforced by automated checks in the pipeline. 4.0.2 also adds the tags that were missing from some modules intended to ship as unstable. Nothing changes in your code: no behavior, signatures or types are affected. The Effect language service builds on these tags to warn you when you use unstable or experimental APIs. Sebastian's post has the full story.

- **OpenTelemetry alignment**: Aligned HTTP, SQL and AI spans with the OpenTelemetry semantic conventions, and brought the OTLP exporter, resource and logger in line with the OpenTelemetry spec. Also preserved active OpenTelemetry parents for Effect spans, left interrupted spans unset, and fixed B3 sampling and zero W3C IDs in HTTP trace context.

- **Additions**: Added a `DatagramSocket` (UDP) module, PowerShell support for `--completions`, a `delay` option on `PersistedQueue.offer`, a deterministic `TestCrypto` layer, a `noFollow` open option and positional reads for `FileSystem`, compact JSON and inspect output for `SchemaError`, and more atom registry APIs.

- **Cluster & workflow**: Fixed orphaned workflow activity recovery after a crash, fixed entity recovery when replayed requests defect during handler rebuild, and avoided workflow replay for self-completed checkpoints. `WithTransaction` replies are now delivered once the transaction outcome is known, with failure replies persisted after rollback. Cluster SQL storage can now run without runtime DDL, and `HashRing.getShards` no longer depends on node history.

- **HTTP, MCP & OpenAPI**: Preserved query strings during router slash normalization, fixed `HttpApi` form and GET payloads rejecting single-value arrays, fixed `HttpStaticServer` `If-Range` validation, and fixed OpenAPI client response inference. On the MCP side, interrupted reverse requests now send cancellation notifications, cancelled HTTP request POSTs get an empty event stream, and stateful extension capabilities are preserved.

- **Streams, SQL & AI**: Fixed `Stream.slidingSize` dropping elements from the final partial window, `Stream.throttle` exceeding its configured rate, and several `tapSink` edge cases. Fixed typed SQL transaction `COMMIT` error recovery and MSSQL pool recovery. Fixed Anthropic streamed tool JSON errors, and cached per-tool response schemas for better AI performance.

- **Continued audit**: The correctness audit carried on after the release, with targeted fixes across STM transactions, `PubSub`, `Queue`, `Pool`, `Channel`, `ScopedCache`, `Layer`, `ManagedRuntime` and Schema union parsing, covering edge cases around interruption, shutdown, retries and resource cleanup.

- **Config, Schema & docs**: Kept `=` inside values when decoding key-value config strings, canonicalized imported JSON Schema pattern sources, and fixed zoned `DateTime` when `Intl` omits fractional seconds. Migration guidance now notes the v4 decoding change in `NumberFromString` and points `parseJson` users to `fromJsonString(Schema.Unknown)`.

You can follow the full changelog in the [effect repository](https://github.com/Effect-TS/effect/commits/main).

To catch up on more updates, check out [Effect v4 Updates](https://www.effect.website/blog?category=effect-v4-updates), starting from the recently published [Effect v4 RC: September 2026 Updates](https://effect.website/blog/effect-v4-rc-september-recap).
