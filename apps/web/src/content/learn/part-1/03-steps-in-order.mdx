Our alert appears in the terminal, but reflex hasn't made a decision yet.
It prints the same message whatever we give it. Let's put our expense rule
to work with two purchases: a laptop costing 1200 and a lunch costing 40.
We want to hear about the laptop, while the lunch can pass without an alert.

Once both expenses have been checked, it would also be useful to see a
summary: `1 of 2 expenses flagged`. To get that right, we'll need to keep
the result of each check and count the ones that matched. This is where
we'll begin writing a sequence of steps, rather than repeating one alert.

The `function*` and `yield*` syntax may be new to you. Together with
`Effect.gen`, they let us write an Effect program as a sequence of steps.
You can read the body from top to bottom. Ordinary calculations stay as
they are; `yield*` is how we run an Effect and wait for its result inside
this function. You don't need a separate lesson on generators to follow
this pattern.

Here, `yield* Effect.log(...)` runs the log before `return flagged` makes
the boolean our result. Calling `evaluate(1200)` still only creates an
Effect; we'll run it in `program` next.

Run the file. You should see `expense 1200 over 500` for the laptop,
`expense 40: no alert` for lunch, and finally `1 of 2 expenses flagged`.
Reflex is making its first decision. The summary comes last because each
`yield*` finishes before the next line starts, so both decisions are
available by the time we count them.

Look back at `yield* evaluate(1200)`. It runs the laptop check and assigns
the result to `laptop`; the lunch check follows the same pattern. Hover
over either result to see that it's a `boolean`, not an Effect. The last
line uses ordinary TypeScript to count them: `filter(Boolean)` keeps the
`true` values, and `length` counts them.

Hover over `evaluate` itself and you'll see
`(amount: number) => Effect<boolean, never, never>`. The `boolean` success
type comes from `return flagged` in its generator.

Hover `program`. The type is `Effect<void, never, never>`. Its generator
has no return value, so the success type is `void`.

## Try it

There's a small mistake worth trying while the program is still short.
What happens if we call `evaluate` but forget to run the Effect it returns?
Remove one `yield*` and follow the result:

1. Delete the `yield*` in front of `evaluate(40)`.
2. Look for a red underline. There is none, and the playground reports no
   errors. Leaving out `yield*` is valid TypeScript.
3. Hover `lunch`. It is now `Effect<boolean, never, never>` instead of
   `boolean`. The changed type reveals the mistake even though TypeScript
   accepts the code.
4. Run the file. The terminal prints `expense 1200 over 500`, then
   `2 of 2 expenses flagged`. The line for 40 is missing, because nothing ran
   that Effect. The summary is wrong, because `lunch` is an Effect, which is
   an object, and `filter(Boolean)` keeps every object.
5. Put the `yield*` back and run the file again. The three lines return.

If you make this mistake later, the missing log line and unexpected Effect
type are useful clues. Creating a description of the check wasn't enough;
we needed `yield*` to run it and get the boolean.

With that restored, both purchases are accounted for. But we've assumed
every expense has an amount. Next we'll try a receipt where that
information is missing and decide how reflex should respond.
