So far the alert is baked into the code: "over 500" lives in `isLarge` and in
the message. But rulebook is supposed to run _your_ rules, and nobody is going
to write those in TypeScript. A **rule** is data. It says what to compare, the
threshold, and what to say when it matches, and it arrives as JSON text, first
from a file and later from an HTTP request. Here is the rule you've been
hard-coding, written as JSON:

  file="lessons/part1/06-untrusted-json/solution/main.ts"
  declaration="largeExpense"
/>

Text from outside your program can contain anything. A rule might use an
operator rulebook doesn't know, or put a string where a number should be. This
lesson is about letting good rules in and stopping bad ones at the door.

You will learn:

- how to describe the shape of your data with a schema;
- how to decode untrusted input into a type you can trust;
- how to read the errors a schema reports.

## Defining a schema

A **schema** describes a shape once. From that one description, Effect derives
both the TypeScript type and a check that runs on real data. Here's the schema
for a rule:

<LessonCode
  file="lessons/part1/06-untrusted-json/solution/main.ts"
  declaration="Rule"
/>

- `Schema.Struct({ ... })` describes an object, with `Schema.String` and
  `Schema.Number` for its fields.
- `Schema.Literals(["gt", "lt"])` describes the operator: one of those two
  strings and nothing else.

Add it to the file, and below it `type Rule = typeof Rule.Type` for the type.
The schema and the type share the name `Rule`, and TypeScript knows which one
you mean from where you use it.

## Evaluating a rule

Now put the rule to work:

1. Replace `isLarge` with a plain function, `matches(rule, amount)`, that
   switches on `rule.op`: `gt` means `amount > rule.value`, and `lt` means
   `amount < rule.value`.
2. Give `evaluate` a second parameter, so it's `evaluate(json, event)`. Its
   first step is `const rule = yield* decodeRule(json)`. The message becomes
   `${event.type} ${event.amount} ${rule.message}` when the rule matches, and
   `${rule.name}: no alert` when it doesn't.
3. Add two rules as JSON strings. `largeExpense` is the rule above. `malformed`
   is broken on purpose:
   `{ "name": "malformed", "op": "greater", "value": "500" }`.
4. Make `program` evaluate `largeExpense` for the laptop, `largeExpense` for
   the taxi, and `malformed` for the laptop.

Notice that the `switch` in `matches` has no `default` branch. TypeScript
knows the operator is one of two strings, so two cases cover everything.

The terminal shows three different outcomes:

- the laptop matches `largeExpense`, and you get the alert;
- the taxi is skipped, just as in lesson 5;
- `malformed` fails with a `SchemaError`, and the program stops.

That last one is the split from lesson 5 again. A missing amount is expected,
so it's a skip. A broken rule is not, so it stops things loudly.

## Reading a schema error

Look at the malformed rule's error in the terminal:

> `SchemaError: Expected "gt" | "lt"` at `["op"]`

It tells you what it expected and where it looked. Decoding stops at the first
problem it finds, so there may be more behind it. `malformed` also has a string
where the value should be a number, and no message at all.

Hover `evaluate`: `Effect<string | void, SchemaError, never>`. The library
defines that failure and reports it for you.

## Try it: add an operator

1. Add `"eq"` to the literals. TypeScript points at `matches`, because its
   `switch` no longer covers every case. Add the `eq` case, `amount === rule.value`.
2. Change `malformed`'s operator to `"between"` and read the error again. The
   list of expected operators now includes `"eq"`.

## Recap

- Data from outside goes through a schema once, at the edge. The rest of the
  program works with a type it can trust.
- `Schema.decodeUnknownEffect(Schema.fromJsonString(...))` parses and checks
  JSON, and fails with a `SchemaError` that says what was wrong and where.
- The cost is a decode on every input and a schema to keep. That's worth it
  where data is untrusted. Values you build yourself in TypeScript, like
  `laptop`, don't need one.
- Lesson 11 grows `Rule` into the real thing, with triggers, actions and more
  operators, and lesson 17 decodes the same JSON from a database column.
