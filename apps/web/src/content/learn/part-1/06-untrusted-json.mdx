Text from outside the program can contain anything. By the end of this lesson
`evaluate` takes a rule as JSON, accepts a valid one, and fails with a clear
error on a broken one.

In this lesson you will:

- describe the shape of a rule with `Schema.Struct`
- decode JSON text into a `Rule` with `Schema.fromJsonString`
- evaluate a decoded rule against an event
- read the error a schema reports

## 1. Define the schema

A **schema** describes a shape once. From that description Effect derives
both the TypeScript type and a check that runs on real data.

Add the schema below the `Event` interface, and the type below it:

<LessonCode
  file="lessons/part1/06-untrusted-json/solution/main.ts"
  declaration="Rule"
/>

- `Schema.Struct({ ... })` describes an object. `Schema.String` and
  `Schema.Number` describe its fields.
- `Schema.Literals(["gt", "lt"])` describes the operator: one of those two
  strings and nothing else.

Then add `type Rule = typeof Rule.Type`. The schema and the type share the
name `Rule`. TypeScript knows which one you mean from where you use it.

`Schema.fromJsonString(Rule)` parses the text and then checks it against the
struct. `decodeRule` takes unknown input and returns an Effect that succeeds
with a `Rule` or fails with a `SchemaError`.

## 4. Read the schema error

Look at the malformed rule's error in the terminal. It reads
`SchemaError: Expected "gt" | "lt"` at `["op"]`. It says what it expected
and where it looked.

Decoding stops at the first problem it finds. `malformed` also has a string
where the value should be a number, and no message at all. Fix the operator
and the next problem is reported.

Hover `evaluate`. Its return type is
`Effect<string | void, SchemaError, never>`. `SchemaError` is defined by the
library and reported for you.

## Try it

Add an operator.

1. Add `"eq"` to the literals. TypeScript underlines `matches`, because its
   `switch` no longer covers every case. Add the `eq` case,
   `amount === rule.value`.
2. Change the operator in `malformed` to `"between"` and run the file. The
   error now lists `"eq"` among the expected operators.

## What you learned

- Data from outside the program goes through a schema once, at the edge.
  The rest of the program works with a type it can trust.
- `Schema.decodeUnknownEffect(Schema.fromJsonString(Rule))` parses and checks
  JSON. It fails with a `SchemaError` that says what was wrong and where.
- Values you build in TypeScript, such as `laptop`, do not need a schema.
- The cost is one decode per input and one schema to maintain.
- [Using FileSystem and NodeRuntime.runMain](/learn/part-2/11-your-program-your-entrypoint)
  grows `Rule` into the real thing, with triggers, actions and more
  operators.
