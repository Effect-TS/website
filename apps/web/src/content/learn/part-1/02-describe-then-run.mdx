It looks like a function call that logs a line. It isn't quite, and that
difference is the idea the rest of the course is built on.

You will learn:

- why an Effect is a description of work rather than the work itself;
- what runs that description;
- how to read the first slot of an Effect's type.

## An Effect is a description

Calling `Effect.log(...)` doesn't log anything. It returns a value that
_describes_ logging. `program` holds that value. You can store it, pass it to
other functions, and combine it with other descriptions, and nothing happens
until something runs it.

That something is the last line of the file, `NodeRuntime.runMain(program)`.
`runMain` takes a description and actually runs it.

This run line stays at the bottom of every Part 1 lesson. The comment above it
says you'll write it yourself in lesson 11. Until then, leave it as it is.

## Reading the type

Hover `program` in the editor. Its type is `Effect<void, never, never>`.

An Effect type has three slots. Only the first one matters today. It is the
value you get back when the effect runs. Logging gives back nothing, so the
first slot says `void`.

The other two slots wait for later lessons. The second is how the effect can
fail (lesson 4), and the third is what it needs before it can run (lesson 8).
Both say `never` here, which means "none".

## Try it: run the value twice

Because `program` is a value, running it twice means combining it with itself.

1. Rename the logging effect to `alert`, so you have a name to reuse.
2. `Effect.andThen(first, second)` describes "run `first`, then `second`". Make
   `program` the combination `Effect.andThen(alert, alert)`.
3. Count the lines in the terminal. There are two, and they come from a single
   description that you built once and ran once.

Hover `program` again. It still says `void`, because logging gives back
nothing, the second time as much as the first.

## Recap

- An Effect is a description of work. Something else runs it, and here that's
  `NodeRuntime.runMain`.
- Because descriptions are values, you can combine them, for example with
  `Effect.andThen`.
- The first slot of the type is what you get back when it runs.
- There is a cost to working this way. A description that nobody runs does
  nothing, and nothing warns you. Lesson 3 shows you what that looks like.
