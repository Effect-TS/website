The file is where lesson 8 left it, red at the run line. Here's why:

- `program` needs a `RuleStore`;
- `runMain` only runs effects that need nothing;
- nothing in the file says which rules the store holds.

So far `RuleStore` is only a shape. In this lesson you give it an
implementation.

You will learn:

- how to build a service with a layer;
- how to supply a layer with `Effect.provide`;
- how to swap one implementation for another without touching the code that
  uses it.

## Building a service with a layer

A **layer** is how a service gets built. Add `Layer` to the `effect` import.

`Layer.effect(RuleStore, effect)` reads as "to get a `RuleStore`, run this
effect and use what it gives back". Put it on the class as
`static readonly layer`, so `RuleStore.layer` sits right next to the
declaration.

The implementation can be a plain `Map` from rule name to JSON:

1. Put `largeExpense` and `malformed` back above the class.
2. Inside `Effect.sync(() => { ... })`, create a `Map` holding both rules.
   `Effect.sync` turns synchronous code into an effect, so the map is created
   when the layer is built, not when the file loads.
3. Return `RuleStore.of({ list: ... })`, where `list` is
   `Effect.sync(() => Array.from(rules.values()))`. `RuleStore.of` checks that
   the object has the service's shape.

## Providing the layer

`Effect.provide(RuleStore.layer)` hands the layer to the program. Add it to
`program` with `.pipe`.

Hover `program`: `Effect<void, SchemaError, never>`. The third slot is back to
`never`, the red line is gone, and the program runs. The laptop gets its alert
from the large expense rule, and then the malformed rule stops the run with
its `SchemaError`, just as it did in lesson 7.

## Try it: swap the implementation

Write a second layer, `layerFixtures`, preloaded with three valid rules:

- `large expense`, as before;
- `within budget`: `lt 5000`, message `under 5000`;
- `very large`: `gt 1000`, message `over 1000`.

Swap it in by changing one line, the `Effect.provide` on `program`.

Notice what you didn't touch. `evaluateAll`, `evaluate` and `program` stay the
same, because they only know the service, not how it was built. Lesson 13
swaps in an in-memory store for tests the same way, and lesson 17 swaps in
SQLite with no change to the code that uses it.

## Recap

- A service is declared once, used with `yield*`, and supplied by a layer.
- Providing the layer takes the service out of the third slot.
- The cost is one more concept and one level of indirection. From
  `yield* RuleStore` you can't jump straight to the code that runs.
- Later you'll meet layers that need other services (lesson 11) and layers
  that clean up after themselves (lesson 18).
