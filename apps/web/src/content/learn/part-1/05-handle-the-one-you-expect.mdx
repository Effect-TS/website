The missing amount stopped the program because you had not yet defined
how to recover. Now make that decision explicit: skip the incomplete
expense, log the reason, and continue to the summary.

The recovery belongs in `evaluate`, where you know what `MissingField`
means for an expense check. Once that error is handled, callers will receive
a boolean instead of a failure for this case, and `MissingField` will no
longer appear in the function's error type.

## Handling MissingField with catchTag

The file starts where the previous lesson ended: `evaluate` fails with
`MissingField` when an event has no amount.

`Effect.catchTag` selects an error by its tag. The handler receives the
typed error and returns an Effect to run in place of the failed computation.
Errors with other tags remain unhandled, so choosing to skip an incomplete
expense will not hide unrelated failures.

The handler logs why the taxi was skipped, using `error.field` from
`MissingField`. It also needs to produce a boolean so that `program` can
continue counting flagged expenses. `Effect.as(effect, value)` runs an
Effect and replaces its successful result with `value`. Here it runs the
log and succeeds with `false`, keeping the skipped expense out of the count.

Every Effect has a `.pipe` method. `effect.pipe(f)` is the same as
`f(effect)`, and `effect.pipe(f, g)` is the same as `g(f(effect))`. It lets
you apply transformations to an Effect in the order you read them. In this
case, the transformation adds error handling to the generator's Effect.

## Checking that the summary returns

Run the file. The terminal prints three log lines:

## The error type after recovery

Hover `evaluate`. Its type is
`(event: Event) => Effect<boolean, never, never>`.

In the previous lesson it was
`(event: Event) => Effect<boolean, MissingField, never>`. `MissingField` has
left the error type because the handler recovers from it. There are no
other typed failures in `evaluate`, so the error type is `never`. The
success type remains `boolean`: both the normal check and the recovery
produce a boolean result.

Hover `program`. The type is `Effect<void, never, never>`. The failure is
gone from `program` too.

## Try it

The replacement result and the error handler serve different purposes.
Remove each in turn to see the difference:

1. In the handler, keep only the `Effect.log(...)` call and remove the
   `Effect.as` around it. Hover `evaluate`. The success type is now
   `boolean | void`, because logging has a `void` result. Run the file. The
   output is the same, since `filter(Boolean)` drops `undefined`, but
   `evaluate` no longer consistently produces a boolean. Put `Effect.as` back.
2. Remove the whole `.pipe(Effect.catchTag(...))`. Hover `evaluate`. The
   error type is `MissingField` again. Run the file. The taxi stops the
   program and the summary is gone. Put the `catchTag` back.

You have chosen to recover from one specific failure, not to ignore errors
in general. In [Validating JSON with Schema](/learn/part-1/06-untrusted-json),
you will introduce a broken rule and leave that failure unhandled so that
it still stops the program.
