The file starts where the previous lesson ended, red at the run line.
`program` needs a `RuleStore`, `runMain` only runs Effects that need
nothing, and nothing in the file says which rules the store holds.

By the end of this lesson `RuleStore` has an implementation, `program` runs
again, and you swap one implementation for another by changing one line.

In this lesson you will:

- build a service with `Layer.effect`
- provide a layer with `Effect.provide`
- swap implementations without touching the code that uses the service

## 1. Build a layer

A **layer** builds a service. `Layer.effect(RuleStore, effect)` reads as "to
get a `RuleStore`, run this Effect and use what it gives back".

Add `Layer` to the `effect` import. Put the `largeExpense` and `malformed`
constants back, above the class. Then add the layer to the class as a static
member, so `RuleStore.layer` sits next to the declaration:

```ts
static readonly layer = Layer.effect(
  RuleStore,
  Effect.sync(() => {
    const rules = new Map([["large expense", largeExpense], ["malformed", malformed]])
    return RuleStore.of({ list: Effect.sync(() => Array.from(rules.values())) })
  })
)
```

- `Effect.sync` turns synchronous code into an Effect. The `Map` is created
  when the layer is built, not when the file loads.
- `RuleStore.of({ list: ... })` checks that the object has the service's
  shape.

## 2. Provide the layer

Attach `Effect.provide(RuleStore.layer)` to `program` with `.pipe`.

Hover `program`. The type is `Effect<void, SchemaError, never>`. The
requirements type is back to `never` and the red line is gone.

Run the file. The laptop gets its alert from the large expense rule, then the
malformed rule stops the run with its `SchemaError`, as it did two lessons
ago.

## What you learned

- A service is defined once, used with `yield*`, and built by a layer.
- `Effect.provide(layer)` supplies the service and removes it from the
  requirements type.
- Swapping a layer changes the implementation without changing the code
  that uses it.
  [Writing tests with @effect/vitest](/learn/part-2/13-first-tests) swaps in
  a test layer this way, and
  [Storing data in SQLite with SqlClient](/learn/part-3/17-survive-a-restart)
  swaps in SQLite.
- The cost is one level of indirection. From `yield* RuleStore` you cannot
  jump straight to the code that runs.
