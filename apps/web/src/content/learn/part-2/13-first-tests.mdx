To check lesson 12, you ran `main.ts`, read the printed run log, and opened
`alerts.log`. That works once. It doesn't work after every change, and it
writes a real file each time.

The Engine's behaviour should live in a test suite that runs in a second and
touches nothing on disk. In this lesson you write the first tests.

You will learn:

- how to write a test that runs an Effect;
- how to give every test a fresh set of services;
- how to assert on a failure you expect;
- how to swap in a fake file system.

## Tests that run Effects

The starter uses `@effect/vitest`, which is vitest with Effect support. Tests
live in `test/`, next to `src/`, and `pnpm test` runs them. Three pieces from
that package do most of the work:

- `it.effect("name", () => effect)` runs an Effect as a test. The test passes
  when the effect succeeds and fails when it fails.
- `layer(SomeLayer)("name", (it) => { ... })` builds the layer and provides it
  to every `it.effect` inside. With `{ buildPerTest: true }`, each test gets a
  fresh build, so one test's rules never leak into the next.
- `assert` has the usual checks: `strictEqual`, `deepStrictEqual`, `match`,
  `isNull`.

The memory stores from lesson 12 are what make this cheap. A test provides
`RuleStore.layerMemory` and starts with an empty store.

## Your first test, red first

Create `test/RuleStore.test.ts` with a test that stores two rules, then lists,
gets and removes them.

Then add the error case. Getting an id that doesn't exist should fail with
`RuleNotFound`. Write it the obvious way first,
`const error = yield* store.get("missing")`, and then assert on `error`.

Run `pnpm test test/RuleStore.test.ts`. The test is red, and vitest prints a
`RuleNotFound` with `id: "missing"`.

Look closely at what happened. The store did the right thing, and the test is
wrong. It treats the failure you expected as a failure of the test.

`Effect.flip` fixes that by swapping the two channels. The failure becomes the
success, so `yield* Effect.flip(store.get("missing"))` gives you the
`RuleNotFound` to assert on. If the store returned a rule instead, the test
would fail. Wrap the call, run the test again, and it's green.

## Revisit: swap a layer, again

The Engine needs a `FileSystem`, and a test shouldn't write `alerts.log`.

`FileSystem.layerNoop` builds a file system where every method does nothing
and fails, except the ones you pass in. Keep a `writes` array in the test file
and pass `writeFileString: (path) => Effect.sync(() => writes.push(path))`,
and the same for `writeFile`. Now every append the Engine makes lands in the
array, and the test can assert what was written without a file ever existing.
(The reference solution uses `FileSystem.makeNoop`, which gives you the same
file system as a plain value that you wrap in `Layer.succeed` yourself. Either
works.)

The Engine's test layer is then `Engine.layer` with `RuleStore.layerMemory`,
`RunLog.layerMemory` and the recording file system. It's the same three-part
build as `main.ts` in lesson 12, with one piece swapped, and `Engine.ts`
doesn't change.

You've made this move before. In lesson 9 you swapped in the fixture store by
changing one line. This time the reason is tests.

## Try it: a missing field is a skip

A missing field is `skipped`, not `failed`. Write the test that says so.
Assert it on the run rows, not only on what `handleEvent` returns, because the
rows are what `runs list` will show and what lesson 17 stores in SQLite.

1. In `test/Engine.test.ts`, store a rule with the `amount gt 500` condition,
   submit `{ type: "expense", description: "no amount" }`, and read the rows
   with `RunLog.list()`. Assert exactly one row, `skipped`, with a `reason`
   that matches `/amount/`, an `error` that is null (a skip is not an error),
   and no writes.
2. Run `pnpm test test/Engine.test.ts`. It's green.
3. Now plant a bug. Change the `MissingField` catch in `src/Engine.ts` to
   `reason: "no match"`. `pnpm check` still passes, because the row is
   well-typed. It's just wrong. Run the test, and it's red:
   `expected 'no match' to match /amount/`.
4. Put `` `missing field ${error.field}` `` back. Green again.

The test filter also matches `checkpoints/13/test/Engine.test.ts`, the
reference tests. They test the checkpoint, not your `src/`, so they stay green
throughout. The hint and the test are in `exercises/13/`.

## Recap

- An `it.effect` test is an Effect, and `layer()` provides what it needs.
- `Effect.flip` lets you assert on a failure you expect.
- A fake service is a layer like any other, and swapping it in doesn't change
  the code under test.
- The cost is keeping fakes honest. The recording file system only knows the
  two methods you gave it.
- In lesson 19 you'll meet `TestClock`, which the reference `RunLog` test uses
  to move time without waiting. In lesson 17 these same suites run against
  SQLite.
