`JSON.parse` returns ordinary JavaScript values. A timestamp is still a string,
a URL is still a string, an array is still an array, and an application class
is not constructed for you. A TypeScript assertion can claim otherwise, but it
does not inspect or transform the value at runtime.

In this tutorial, we will start with a conventional `node:http` endpoint and
replace that assertion with one Schema-driven boundary. The finished
`POST /orders` endpoint will have these observable behaviors:

| Request                                     | Boundary behavior                              | HTTP result |
| ------------------------------------------- | ---------------------------------------------- | ----------- |
| Valid order JSON                            | Builds rich values, then encodes response JSON | `201`       |
| Wrong field type                            | Stops before order logic                       | `400`       |
| Order id without the required `ord_` prefix | Stops before constructing the domain `OrderId` | `400`       |

The HTTP server will remain ordinary TypeScript. Schema will own the two jobs
at the boundary: decoding unknown request data into domain values and encoding
domain values into JSON-safe response data.

## 1. Start with a familiar JSON endpoint

This tutorial requires Node.js 22.18.0 or newer because it runs `server.ts`
directly with Node's built-in TypeScript support.

To create the project manually, run:

```sh title="Create the project"
mkdir preserve-domain-types
cd preserve-domain-types
npm init -y
npm pkg set type=module
npm install --save-dev @types/node@22
```

Create `server.ts` with this conventional implementation:

```ts title="server.ts" collapse={19-34,46-50}
import { createServer } from "node:http"

class OrderId {
  readonly value: string

  constructor(value: string) {
    this.value = value
  }
}

interface OrderSubmission {
  readonly orderId: OrderId
  readonly quantity: number
  readonly requestedAt: Date
  readonly callbackUrl: URL
  readonly labels: ReadonlySet<string>
}

const server = createServer(async (request, response) => {
  const sendJson = (status: number, body: unknown): void => {
    response.writeHead(status, { "content-type": "application/json" })
    response.end(JSON.stringify(body))
  }

  if (request.method !== "POST" || request.url !== "/orders") {
    sendJson(404, { error: "NotFound" })
    return
  }

  try {
    let body = ""
    for await (const chunk of request) {
      body += chunk
    }

    const submission = JSON.parse(body) as OrderSubmission

    console.log({
      orderIdIsOrderId: submission.orderId instanceof OrderId,
      requestedAtIsDate: submission.requestedAt instanceof Date,
      callbackIsUrl: submission.callbackUrl instanceof URL,
      labelsAreSet: submission.labels instanceof Set,
    })

    sendJson(201, { ...submission, status: "accepted" })
  } catch (error) {
    console.error(error)
    sendJson(500, { error: "InternalServerError" })
  }
})

server.listen(3000, () => console.log("Listening on http://localhost:3000"))
```

Start the server with `--watch`. Node.js will reload the file after every edit,
so keep this terminal running throughout the tutorial:

`orderId`, `requestedAt`, and `callbackUrl` are strings, while `labels` is an
array. Calling an `OrderId` method, a date method, or `Set.prototype.has` would
fail even though the editor says those operations are allowed.

A Schema is an immutable value that describes which inputs are accepted and
what value decoding produces. Defining or composing one does not inspect any
request. The decoder created from it performs that work when the handler calls
`decodeOrderSubmission`.

<EffectApi
  name="Schema.Struct"
  href="/docs/v4/api/effect/Schema#Struct-function"
>
  Combines property schemas into an object schema. Here every request must have
  `orderId`, `quantity`, `requestedAt`, `callbackUrl`, and `labels` with the
  shapes declared inside the object.
</EffectApi>

<EffectApi
  name="Schema.String"
  href="/docs/v4/api/effect/Schema#String-variable"
>
  Describes a JavaScript string. It validates the three string fields in this
  first boundary schema and also supplies the element schema inside `labels`.
</EffectApi>

<EffectApi
  name="Schema.Finite"
  href="/docs/v4/api/effect/Schema#Finite-variable"
>
  Describes a finite JavaScript number. The decoded `quantity` is a `number`,
  while `NaN`, positive infinity, negative infinity, strings, and other values
  are rejected.
</EffectApi>

<EffectApi name="Schema.Array" href="/docs/v4/api/effect/Schema#Array-variable">
  Builds an array schema from an element schema. `Schema.Array(Schema.String)`
  therefore requires an array in which every label is a string.
</EffectApi>

<EffectApi
  name="Schema.decodeUnknownResult"
  href="/docs/v4/api/effect/Schema#decodeUnknownResult"
>
  Creates a decoder for untrusted input. Calling it returns a `Result`: success
  contains the decoded object, while failure contains a `SchemaError` that
  describes why the value did not match. Nothing is thrown for a shape error.
</EffectApi>

<EffectApi name="Result.isFailure" href="/docs/v4/api/effect/Result#isFailure">
  Checks whether a `Result` is its failure case. Inside the `if`, TypeScript
  knows decoding failed; after the early return, it knows `decoded.success` is
  available.
</EffectApi>

Decoding and encoding are directional terms. Decoding moves from data at the
boundary into data used by the application. Encoding, which we will add later,
moves an application value back toward its boundary representation.

## 4. Decode JSON into useful runtime values

The shape is safe, but order logic still receives strings and an array. Change

The `OrderSubmission` schema describes domain values. The derived
`OrderSubmissionJson` codec describes how those values cross JSON. A codec is a
schema that keeps both directions. In this codec, its decoded `Type` contains a
`DateTime.Utc`, a `URL`, and a `ReadonlySet<string>`. Its `Encoded` side contains
the JSON-compatible ISO string, URL string, and string array.

<EffectApi
  name="Schema.DateTimeUtc"
  href="/docs/v4/api/effect/Schema#DateTimeUtc-variable"
>
  Describes an immutable Effect `DateTime.Utc` value that represents an instant
  in UTC. It is a different runtime type from JavaScript `Date`. Its canonical
  JSON codec decodes a UTC ISO string such as `2026-08-09T10:00:00.000Z` into
  that value and encodes the value back to a UTC ISO string.
</EffectApi>

<EffectApi name="Schema.URL" href="/docs/v4/api/effect/Schema#URL-variable">
  Describes a JavaScript `URL` instance. Its canonical JSON codec accepts a
  valid URL string, constructs `URL`, and turns the instance back into a string
  during encoding.
</EffectApi>

<EffectApi
  name="Schema.ReadonlySet"
  href="/docs/v4/api/effect/Schema#ReadonlySet-function"
>
  Builds a schema for a JavaScript `ReadonlySet`. The inner schema validates its
  elements. Its canonical JSON codec decodes a JSON array into `Set` and encodes
  the set back into an array.
</EffectApi>

<EffectApi
  name="Schema.toCodecJson"
  href="/docs/v4/api/effect/Schema#toCodecJson-function"
>
  Derives a JSON-compatible codec recursively. In this object it selects the ISO
  string representation for `DateTime.Utc`, a string for `URL`, and an array for
  `ReadonlySet`, while ordinary strings and numbers stay unchanged.
</EffectApi>

<EffectApi
  name="DateTime.formatIso"
  href="/docs/v4/api/effect/DateTime#formatIso"
>
  Formats a `DateTime` value as an ISO string. Calling it here demonstrates that
  `requestedAt` is no longer the request's original JavaScript string.
</EffectApi>

## 5. Encode the response through Schema

Define the accepted response as domain data, derive its JSON codec, and encode

## Read the final boundary

`OrderSubmission` and `AcceptedOrder` describe the runtime values used by the
application. `Schema.toCodecJson` derives the boundary representations of those
same definitions. `Schema.decodeUnknownResult` protects incoming data, while
`Schema.encodeResult` protects outgoing data.

There is no assertion, replacer, reviver, or field-by-field reconstruction in
the HTTP handler. When a domain field changes, its schema keeps validation,
decoding, and encoding together.
