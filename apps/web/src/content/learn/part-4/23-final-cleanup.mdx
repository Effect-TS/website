Each lesson since
[Using FileSystem and NodeRuntime.runMain](/learn/part-2/11-your-program-your-entrypoint)
added a layer where it was needed. The server's stack grew in
`src/server/main.ts`, one `Layer.provide` at a time. The CLI's stack grew in
its run line. Both work, but neither file shows at a glance what the program
runs on.

In this lesson you move both stacks into one file, `src/Layers.ts`. The
program's behaviour does not change.

In this lesson you will:

- move the server's and the CLI's layers into `src/Layers.ts`
- reduce each entrypoint to one `provide` or one `launch`
- confirm that the program still produces the same rows

## 1. Move both stacks into Layers.ts

Create `src/Layers.ts`. Move the server's stack there as an exported value
named `server`, and the CLI's stack as an exported value named `cli`:

The layers are the same ones you built during the course. Only their location

Engine is built after the stores and SQLite, and closed before them.

## 2. Shrink the entrypoints

Replace the server's stack with the exported layer. The server entrypoint now
only launches it:

<LessonCode file="checkpoints/23/src/server/main.ts" />

In `src/cli/main.ts`, replace the CLI's stack with `Effect.provide(Layers.cli)`.
That is the CLI's only `provide`.

Leave the `Effect.provideService` calls inside the Engine where they are. They
hand one call a service the Engine already holds, which is a different job
from building the program's layers.

## 3. Check that nothing changed

Run `pnpm check` and `pnpm test`. Both pass.

Then repeat the run from
[Diagnosing a request from its trace](/learn/part-3/22-diagnose-it)
from an empty `reflex.db`. Your server produces the same four rows.

## What you learned

- One file, `src/Layers.ts`, now says what each program runs on.
- An entrypoint does one thing: `Layer.launch` for the server, one
  `Effect.provide` for the CLI.
- `Effect.provideService` inside a service is not a layer stack. It stays
  where it is.
