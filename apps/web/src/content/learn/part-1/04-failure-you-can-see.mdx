Every expense so far came with an amount. Real ones don't always. Here is a
taxi receipt exactly as it arrived: `{ type: "expense" }`. No `amount`.

Ask `isLarge` about it and there is no honest answer: it isn't over 500, and
it isn't under 500 either. Nobody has checked this expense, and the summary
you wrote in the previous lesson should not count it as if someone had.

So `evaluate` needs a way to say "I couldn't do this one", and that way should
show up in its type, so the rest of the program has to deal with it. In Effect
that is a failure. In this lesson you will make `evaluate` fail on a missing
field, watch the failure appear in the type of `evaluate`, and see what it
does to the program when it runs: the taxi stops it, and the summary never
prints. In the next lesson you decide what to do about that.

In this lesson you will:

- describe an expense as an event with an optional field
- define an error class with `Schema.TaggedError`
- fail an Effect with that error
- read the error type of an Effect

## 3. Defining an error

Add `Schema` to the `effect` import. Then declare `MissingField` between the
interface and the two expenses:

<LessonCode
  file="lessons/part1/04-failure-you-can-see/solution/main.ts"
  declaration="MissingField"
/>

`Schema.TaggedError` is called twice:

- The first call, `<MissingField>()`, takes the class's own name, so the
  class can refer to its own type.
- The second call takes a **tag** and the **fields**. The tag,
  `"MissingField"`, is how you pick this error out later. The fields say what
  the error carries. This one carries the name of the missing `field`.

`Schema` gets its own lesson,
[Validating JSON with Schema](/learn/part-1/06-untrusted-json). Here it only
lists what the error carries.

At the top of the `Effect.gen` block in `evaluate`, check for the amount. If
it is missing, fail:

<LessonCode
  file="lessons/part1/04-failure-you-can-see/solution/main.ts"
  declaration="evaluate"
/>

`return yield* new MissingField({ field: "amount" })` fails the Effect with
that error. `return` tells TypeScript that this path ends here, so after the
check `event.amount` is a number and the red underline is gone.

Hover `evaluate`. Its type is
`(event: Event) => Effect<boolean, MissingField, never>`. The error type was
`never`. Now it names `MissingField`, so anything that runs `evaluate` can see
that it may fail, and with what.

## 5. Run it

Run the file. The terminal prints `expense 1200 over 500` for the laptop.
Then it reports a `MissingField` failure for the taxi, and the program stops.
`1 of 2 expenses flagged` never appears. A failure ends the `Effect.gen`
block it happens in, and every block that ran it with `yield*`, so the line
after `yield* evaluate(taxi)` never runs.

Hover `program`. The type is `Effect<void, MissingField, never>`. `program`
does not create the error, but it runs `evaluate`, so the failure is part of
its type too.

## Try it

An event can also be something other than an expense.

1. Declare a second error, `NotAnExpense`, the same way as `MissingField`.
   Give it a `type` field.
2. At the top of the `Effect.gen` block in `evaluate`, fail with it when
   `event.type` is not `"expense"`.
3. Hover `evaluate`. The error type now lists both errors, as a union such
   as `NotAnExpense | MissingField`. Every failure an Effect can produce
   joins that union, and `program` shows the same union.

This is practice only. The next lesson starts from the file without
`NotAnExpense`.

## What you learned

- An event is a small object that says what happened. Its fields can be
  missing.
- `Schema.TaggedError` defines an error class with a tag and typed fields.
- `return yield* new MissingField(...)` fails an Effect with that error and
  ends the current path.
- The error type of an Effect lists the failures it can produce, including
  the failures of the Effects it runs.
- A failure stops the program at the step that failed. Nothing after it runs.
- Each failure is one class. In
  [Serving an HTTP API with HttpApi](/learn/part-2/14-serve-it) these classes
  travel over HTTP, which is why they are built from `Schema`.
