## Using the FileSystem service

To read those files and append to `alerts.log`, rulebook needs the file
system. Effect ships it as a service, `FileSystem.FileSystem`, and you use it
exactly like your own `RuleStore` from lesson 8:

- `const fs = yield* FileSystem.FileSystem` gets it, and puts it in the third
  slot of whatever uses it.
- `fs.readFileString(path)` reads a file.
- `fs.writeFileString(path, text, { flag: "a" })` appends to a file, creating
  it if it's missing.

Both fail with a `PlatformError` when the disk says no.

Something has to provide the service. `NodeServices.layer`, from
`@effect/platform-node`, is a layer with Node's implementation of `FileSystem`
and the other services the platform ships. In lesson 13 you'll replace it with
a fake file system for tests, without changing any code that uses it.

## Writing your own run line

In Part 1 the run line was supplied, with a comment saying you'd write it
yourself in lesson 11. This is lesson 11.

`NodeRuntime.runMain` runs the program and keeps the process alive until it's
done. It sets the exit code, 0 on success and 1 on failure. It also turns
Ctrl-C into an interruption, which lesson 18 relies on.

Your run line has three steps:

1. Print a typed error as one line with `Effect.tapError`. It runs an effect
   on the failure, then passes the failure on unchanged.
2. Add `Effect.provide(NodeServices.layer)`, so the program has its
   `FileSystem`.
3. Call `NodeRuntime.runMain({ disableErrorReporting: true })`. Error reporting
   is off because step 1 already printed the error.

## Revisit: a schema with variants

The lesson 6 schema had one shape. A real rule comes in variants. A trigger is
either an `event` or an `interval`, and an action is either `appendFile` or
`httpPost`.

Each variant is a `Schema.Struct` with a `type` literal, and `Schema.Union`
joins them. Because every variant has a different `type`, TypeScript can
narrow on it. Inside `case "appendFile":`, the compiler knows that
`rule.action.path` exists.

The condition grows too:

- `field` is now a dotted path, such as `body.status`;
- the fifth operator, `contains`, is in;
- `lookup` fails with `MissingField` when a key on the path is absent.

## Revisit: errors you can name

A `PlatformError` from `writeFileString` is the file system's error, in the
file system's vocabulary. Whoever called the rule only wants to know that the
action didn't happen.

`Effect.mapError` turns one failure into another. Here it turns the
`PlatformError` into an `ActionFailed`, with the reason `io` and the original
message. `io` is one of three reasons a failed action can have. The other two,
`status` and `timeout`, arrive with `httpPost` in lesson 20.

## Try it: write the rule's message

Every alert line reads like `expense 1200 over 500`, because `alertLine`
builds it from the event. But the rule files already say what they want
written: `"message": "expense over 500"`. Make the action write the rule's
message instead:

1. Add `message: Schema.String` to the `AppendFile` struct.
2. In the `appendFile` case, hover `rule.action.message`. It's a `string`.
   Write it instead of the built line.
3. Delete `alertLine`, which has no caller left, and `words` along with it.
4. Remove `message` from a copy of the rule file, run it, and read the error.
   Notice that it names the missing key and its path.

To check your work, run
`pnpm tsx src/run-once.ts fixtures/rules/expense.json fixtures/events/laptop.json`.
It should append `expense over 500` to `alerts.log`. The hint and the changed
files are in `exercises/11/`. From lesson 12 on, the checkpoints include this
change.

## Recap

- A service Effect ships is used exactly like one you wrote, and a layer
  supplies its real implementation.
- `NodeRuntime.runMain` is your run line now. It sets the exit code and turns
  Ctrl-C into an interruption.
- `Schema.Union` of structs with a `type` literal describes variants that
  TypeScript can narrow.
- `Effect.mapError` turns a low-level error into one your caller understands.
- The cost of all this is one more `provide` at the edge of the program. In
  lesson 13 you'll swap in a fake `FileSystem` for tests, and in lesson 16
  you'll add a telemetry layer that sends your spans to the trace viewer.
