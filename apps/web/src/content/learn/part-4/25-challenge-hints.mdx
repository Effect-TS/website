## Where the state lives

The Engine already owns everything that runs a rule: the `FiberMap` of loops
from lesson 19, and `handleEvent` from lesson 21. Whether a rule is paused can
live right next to them, in the Engine layer, as a set of ids.

The run log doesn't need a new outcome. A paused rule doesn't run, so it
writes nothing.

## Pause and resume

`stop` already interrupts a loop and waits for its last row. Pausing an
interval rule is that, plus remembering the pause. Do it in that order:
remember the pause first, then stop the loop, so no event can run the rule
while its loop is stopping.

Resuming is the reverse. Forget the pause, then call `start`.

For an event rule, `handleEvent` leaves paused rules out of the rules it runs.
They get no `Engine.execute` span at all.

## rules list

For interval rules, the `list` handler asks the Engine `isRunning`. It can ask
whether a rule is paused in the same way, and say `paused` before it says
`running` or `stopped`. `ListedRule` in `src/api/Api.ts` needs the new
literal.

## The endpoints

Add `pause` and `resume` to the `rules` group in `src/api/Api.ts`, next to
`remove`:

- `POST /rules/:id/pause`
- `POST /rules/:id/resume`

Each one declares `RuleNotFound` as its 404 error. Each handler looks the rule
up with `store.get` first, so an unknown id fails with `RuleNotFound`, exactly
as `remove` does.

The CLI gets both endpoints from `ApiClient` with no extra code. The two new
commands catch `RuleNotFound` the same way `rules remove` does.

## The tests

All four tests go on the lesson 19 harness.

- **The interval test** is the lesson 19 core test, with pause in place of
  remove. Await `remote.arrived`, pause, `TestClock.adjust` past
  `everySeconds`, and assert that `remote.requests.length` didn't grow and the
  run rows didn't change.
- **The positive control** keeps the poll hanging. Resume starts the loop, and
  its first tick runs at once, so that tick is the one new request and its
  `started` row is the one new row. Adjust past one interval, but stay short of
  the 10 second timeout. That way the hanging tick neither times out nor makes
  room for another, and you can assert exactly one more request and one more
  row. A poll that answered would let the next tick run within the same
  adjustment, and you'd get two.
- **The event test** uses the `HttpApiTest` client from lesson 19 and the
  outcomes that `events.submit` returns.
- **The unknown id test** uses `Effect.flip` on `pause` to get the
  `RuleNotFound`, as in lesson 13.

## A restart

Keeping the pause in memory is a fair answer. A server start already restarts
stopped loops, so a restart also resumes paused ones. Say so in a comment.

If you want a pause to survive a restart, it needs a column and a migration.
That takes longer than 40 minutes.
