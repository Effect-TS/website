This page is a reference for Part 1. The editor holds the whole file from
the previous lesson. There is nothing new to write. The file runs and prints
the three alert lines and three skips from
[Providing a service with a layer](/learn/part-1/09-provide-it).

Use it to check that you can read every name in the file before you move to
your own machine.

## The types in the file

Hover each name, from top to bottom. Before you hover, say what you expect
in each type parameter: the success type, the error type and the
requirements type.

| Name           | Type                                                            | Notes                                                      |
| -------------- | --------------------------------------------------------------- | ---------------------------------------------------------- |
| `Rule`         | a schema; `type Rule` is the type derived from it               | the hover lists the rule's fields                          |
| `decodeRule`   | takes unknown input, returns `Effect<Rule, SchemaError, never>` | parses JSON text and checks it                             |
| `RuleStore`    | a service, with `layer` and `layerFixtures` as static members   | key `reflex/RuleStore`                                     |
| `MissingField` | an error class with one field, `field`                          | the one error you declared and still use                   |
| `matches`      | `(rule: Rule, amount: number) => boolean`                       | a plain function, no Effect                                |
| `evaluate`     | returns `Effect<boolean, SchemaError, never>`                   | a missing field is handled inside, a malformed rule is not |
| `evaluateAll`  | returns `Effect<void, SchemaError, RuleStore>`                  | needs the store                                            |
| `program`      | `Effect<void, SchemaError, never>`                              | the store is provided                                      |

If one of them surprises you, look it up in the table below and reread the
lesson that introduced it.

## Optional challenges

These are not counted in the course time, and Part 2 does not depend on
them.

1. **`eq` and `neq` operators.** Add "equal to" and "not equal to". Start
   with the schema, then follow what TypeScript asks of `matches`.
2. **A `skipped` result with a reason.** Instead of logging a skip and giving
   back `false`, make `evaluate` give back a value that says the rule was
   skipped and why. The hover then shows that value's type alongside
   `boolean`, because a checked expense still gives back `flagged`.
   [Recording runs with Effect.onExit](/learn/part-2/12-an-engine-that-records)
   does a version of this.
3. **A second kind of event.** Add an event that is not an expense, such as a
   battery level, and a rule for it. The alert message reads `event.amount`.
   Make it right for an event that has no amount.
